# 9. Формы и клиент-серверное взаимодействие

[↑ Оглавление](./README.md)

> Как работать с сервером из формы и как организовать модуль формы.

**Коротко**

- На одно действие пользователя — не больше одного вызова сервера.
- По умолчанию — `&НаСервереБезКонтекста`. Контекстный вызов — только когда без него не обойтись.
- Логика живёт в модулях объектов и менеджеров, форма её только вызывает.
- В форме объекта есть `ПриЧтенииСозданииНаСервере` — для корректной работы «Перечитать».

## Правила

### 9.1 Вызовы сервера

- **9.1.1** На одно действие пользователя — не больше одного обращения к серверу.
- **9.1.2** Сервер вызывается без контекста (`&НаСервереБезКонтекста`, `&НаКлиентеНаСервереБезКонтекста`). Контекстный вызов (`&НаСервере`) — только когда без данных формы действительно не обойтись.
- **9.1.3** Контекст формы не раздувается без необходимости, особенно большими структурами: каждый контекстный вызов передаёт его на сервер и обратно.
- **9.1.4** Из событий, где контекстный вызов запрещён, сервер с контекстом не вызывается (см. синтакс-помощник по событию). В событиях `ПриАктивизации*` сервер не вызывается совсем, даже без контекста; если без этого не обойтись — через обработчик ожидания.
- **9.1.5** Параметры серверных методов передаются через `Знач` (см. [4.2.2](./04_methods.md#42-параметры)).
- **9.1.6** Большая коллекция, которую сервер всё равно перезаполнит, очищается на клиенте до вызова: незачем гонять на сервер данные, которые там сразу удалят.

<details><summary>Примеры к 9.1</summary>

Вызов без контекста:

```bsl
// ❌ Плохо: контекст формы не нужен, но уходит на сервер целиком
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
	ДоговорЗаполнитьНаСервере();
КонецПроцедуры

&НаСервере
Процедура ДоговорЗаполнитьНаСервере()
	Объект.Договор = пр_Договор.Основной(Объект.Контрагент, Объект.Организация);
КонецПроцедуры

// ✅ Хорошо: на сервер уходят только два значения
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
	Объект.Договор = ДоговорОсновной(Объект.Контрагент, Объект.Организация);
КонецПроцедуры

// Основной договор контрагента с организацией.
&НаСервереБезКонтекста
Функция ДоговорОсновной(Знач Контрагент, Знач Организация)

	Результат = пр_Договор.Основной(Контрагент, Организация);

	Возврат Результат;

КонецФункции
```

Один вызов вместо нескольких:

```bsl
// ❌ Плохо: три обращения к серверу на одно изменение
&НаКлиенте
Процедура НоменклатураПриИзменении(Элемент)
	ТекущиеДанные = Элементы.Товары.ТекущиеДанные;
	ТекущиеДанные.Цена = НоменклатураЦена(ТекущиеДанные.Номенклатура);
	ТекущиеДанные.СтавкаНДС = НоменклатураСтавкаНДС(ТекущиеДанные.Номенклатура);
	ТекущиеДанные.Единица = НоменклатураЕдиница(ТекущиеДанные.Номенклатура);
КонецПроцедуры

// ✅ Хорошо: все данные строки — за один вызов
&НаКлиенте
Процедура НоменклатураПриИзменении(Элемент)
	ТекущиеДанные = Элементы.Товары.ТекущиеДанные;
	НоменклатураДанные = НоменклатураРеквизиты(ТекущиеДанные.Номенклатура);
	ЗаполнитьЗначенияСвойств(ТекущиеДанные, НоменклатураДанные);
КонецПроцедуры
```

Активизация строки:

```bsl
// ❌ Плохо: обращение к серверу при каждом перемещении по списку
&НаКлиенте
Процедура СписокПриАктивизацииСтроки(Элемент)
	ОстатокОбновитьНаСервере();
КонецПроцедуры

// ✅ Хорошо: обновление после паузы, когда пользователь остановился на строке
&НаКлиенте
Процедура СписокПриАктивизацииСтроки(Элемент)
	ПодключитьОбработчикОжидания("ОстатокОбновить", 0.2, Истина);
КонецПроцедуры

// Обновляет остаток по текущей строке списка.
&НаКлиенте
Процедура ОстатокОбновить()
	// ...
КонецПроцедуры
```

Очистка коллекции перед перезаполнением:

```bsl
// ✅ Хорошо: строки удаляются на клиенте, на сервер уходит пустая таблица
&НаКлиенте
Процедура ТоварыПерезаполнить(Команда)

	Объект.Товары.Очистить();
	ТоварыЗаполнитьНаСервере();

КонецПроцедуры
```

</details>

### 9.2 Модуль формы

- **9.2.1** Обработчики событий одного элемента формы стоят рядом.
- **9.2.2** У каждого события свой обработчик. Одинаковые действия для разных элементов выносятся в отдельный метод, который вызывают обработчики. Исключение — программный вызов обработчика, когда код выполняет действие, которое по логике должно его вызвать.
- **9.2.3** В форме хранимого объекта есть оба обработчика — `ПриСозданииНаСервере` и `ПриЧтенииНаСервере` — и общий метод `ПриЧтенииСозданииНаСервере`, который вызывается из обоих. В нём выполняется всё, что зависит от данных объекта. Так форма правильно работает при стандартной команде «Перечитать».
- **9.2.4** Логика, не зависящая от формы, в модуле формы не пишется (см. [3.1.2](./03_modules.md#31-размещение-кода)).

<details><summary>Примеры к 9.2</summary>

Общий метод вместо вызова чужого обработчика (9.2.2):

```bsl
// ❌ Плохо: один обработчик назначен событиям разных элементов
// (в свойствах ДатаНачала и ДатаОкончания указан один и тот же «ДатаПриИзменении»)
&НаКлиенте
Процедура ДатаПриИзменении(Элемент)
	ПериодПроверить();
КонецПроцедуры

// ✅ Хорошо: у каждого элемента свой обработчик, общий код — в методе
&НаКлиенте
Процедура ДатаНачалаПриИзменении(Элемент)
	ПериодПроверить();
КонецПроцедуры

&НаКлиенте
Процедура ДатаОкончанияПриИзменении(Элемент)
	ПериодПроверить();
КонецПроцедуры
```

Чтение и создание формы объекта (9.2.3):

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

	// Действия, не зависящие от данных объекта
	СписокВыбораСтатусовЗаполнить();

	// Для нового объекта ПриЧтенииНаСервере не вызывается
	Если Параметры.Ключ.Пустая() Тогда
		ПриЧтенииСозданииНаСервере();
	КонецЕсли;

КонецПроцедуры

&НаСервере
Процедура ПриЧтенииНаСервере(ТекущийОбъект)

	ПриЧтенииСозданииНаСервере();

КонецПроцедуры

// Настройка формы по данным объекта: вызывается при создании и при каждом чтении.
&НаСервере
Процедура ПриЧтенииСозданииНаСервере()

	ДоставкаВидимостьУстановить();
	ТоварыИтогиРассчитать();

КонецПроцедуры
```

</details>

### 9.3 Прочее

- **9.3.1** Картинки в формах и командах — PNG с прозрачным фоном. BMP не используется: он некорректно отображается в веб-клиенте.
- **9.3.2** Форма, которая имеет смысл только в контексте другой формы, не открывается без владельца — например, из меню «Все функции». В этом случае показывается понятное сообщение.
- **9.3.3** Формы списка и выбора — разные. Исключение — если это приводит к заметному дублированию кода: тогда одна форма, которая корректно обрабатывает режим выбора.

<details><summary>Пример к 9.3.2</summary>

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

	Если НЕ ЗначениеЗаполнено(Параметры.Заказ) Тогда
		ОбщегоНазначения.СообщитьПользователю(пр_ПодборТекстыКлиентСервер.ОткрытиеИзЗаказа(), , , , Отказ);
		Возврат;
	КонецЕсли;

	// ...

КонецПроцедуры
```

</details>

## Пояснения

### Почему вызовы сервера так важны

Каждый вызов сервера — это сеть и сериализация данных. В веб-клиенте или на медленном канале лишний вызов пользователь замечает сразу. Контекстный вызов вдобавок гоняет туда и обратно все данные формы. Поэтому:

- соберите на клиенте всё, что нужно для операции, и сделайте один вызов;
- по умолчанию выбирайте `&НаСервереБезКонтекста`, а `&НаСервере` — только по необходимости;
- следите за размером формы: лишние реквизиты и элементы замедляют каждый контекстный вызов, а замеры времени кода это показывают не всегда.

### Простые формы

Форма, перегруженная реквизитами и элементами, работает медленнее и труднее для пользователя. Чем проще форма — при достаточном функционале, — тем легче с ней работать.
