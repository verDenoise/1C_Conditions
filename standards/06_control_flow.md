# 6. Условия и циклы

[↑ Оглавление](./README.md)

> Как писать ветвления и циклы, чтобы основной сценарий читался с первого взгляда.

**Коротко**

- Основной вариант — в `Если`, исключительный — в `Иначе`.
- Сложное условие получает имя: функцию или булеву переменную.
- Никаких пустых веток, двойных отрицаний и сравнений с `Истина`.
- Тело цикла — короткое, вложенность — не больше трёх уровней.

## Правила

### 6.1 Условия

- **6.1.1** Каждое ветвление удваивает число путей выполнения, поэтому ветвлений должно быть как можно меньше. Пороги сложности метода — как у [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) по умолчанию: когнитивная сложность не больше 15, цикломатическая — не больше 20. Превышение обосновывается комментарием. Если в проекте пороги BSL LS изменены, действуют настройки проекта.
- **6.1.2** Основной, ожидаемый вариант обрабатывается в ветке `Если`, а не в `Иначе`.
- **6.1.3** Ветки `ИначеЕсли` идут в порядке убывания вероятности. Исключение — перебор законченного набора (значений перечисления, предопределённых элементов): тогда порядок веток повторяет порядок значений.
- **6.1.4** Сложное условие заменяется функцией или промежуточными булевыми переменными. Условие, которое нужно больше одного раза, обязательно выносится в функцию.
- **6.1.5** Длинная цепочка условных операторов выносится в отдельный метод.
- **6.1.6** Порядок вычисления сложных логических выражений задаётся скобками.
- **6.1.7** Пустая ветка `Если` запрещена: условие инвертируется, а код из `Иначе` переносится в `Если`.
- **6.1.8** Булевы значения не сравниваются с `Истина` и `Ложь`.
- **6.1.9** Двойное отрицание запрещено.
- **6.1.10** Простой выбор из двух значений записывается тернарным оператором `?()`. Вложенные тернарные операторы запрещены.
- **6.1.11** Вложенность управляющих конструкций — `Если`, циклов, `Попытка` — не больше трёх уровней. Глубже — выносим вложенную часть в метод.

<details><summary>Примеры к 6.1</summary>

Основной вариант первым:

```bsl
// ❌ Плохо: сначала приходится продираться через исключительный случай
Если НЕ ЗначениеЗаполнено(Договор) Тогда
	ДоговорОшибкаСообщить(Отказ);
Иначе
	ДоговорУсловияПрименить(Договор);
	ДоговорСрокиРассчитать(Договор);
	ДоговорЛимитПроверить(Договор, Отказ);
КонецЕсли;

// ✅ Хорошо
Если ЗначениеЗаполнено(Договор) Тогда
	ДоговорУсловияПрименить(Договор);
	ДоговорСрокиРассчитать(Договор);
	ДоговорЛимитПроверить(Договор, Отказ);
Иначе
	ДоговорОшибкаСообщить(Отказ);
КонецЕсли;
```

Перебор законченного набора — в порядке значений:

```bsl
Если ВидДоставки = Перечисления.пр_ВидыДоставки.Самовывоз Тогда
	// ...
ИначеЕсли ВидДоставки = Перечисления.пр_ВидыДоставки.Курьер Тогда
	// ...
ИначеЕсли ВидДоставки = Перечисления.пр_ВидыДоставки.ТранспортнаяКомпания Тогда
	// ...
КонецЕсли;
```

Сложное условие:

```bsl
// ❌ Плохо: смысл приходится восстанавливать. И в условии уже есть ошибка: «И» выполняется
// раньше «ИЛИ», поэтому статус проверяется только для договоров поставки
Если (Договор.Вид = ВидАгентский И Договор.КомиссияУчитывается И Ставки.Получить(Договор.Ставка) <> Неопределено)
	ИЛИ (Договор.Вид = ВидПоставки И Договор.ДатаОкончания <= КонецМесяца(ДатаРасчета))
	И Договор.Статус = Перечисления.пр_СтатусыДоговоров.Действует Тогда

// ✅ Хорошо: у каждой части есть имя, порядок вычисления задан скобками
КомиссияНачисляется = пр_ДоговорКомиссия.Начисляется(Договор, Ставки);
ПоставкаЗавершается = пр_ДоговорПоставка.ЗавершаетсяВМесяце(Договор, ДатаРасчета);
ДоговорДействует = (Договор.Статус = Перечисления.пр_СтатусыДоговоров.Действует);

Если (КомиссияНачисляется ИЛИ ПоставкаЗавершается) И ДоговорДействует Тогда
```

Пустая ветка:

```bsl
// ❌ Плохо
Если Документ.Проведен Тогда
	// ничего не делаем
Иначе
	ДокументПровести(Документ);
КонецЕсли;

// ✅ Хорошо
Если НЕ Документ.Проведен Тогда
	ДокументПровести(Документ);
КонецЕсли;
```

Сравнение с `Истина` и лишнее ветвление:

```bsl
// ❌ Плохо
Если ПроверкаПройдена = Истина ИЛИ ПроверкиОтключены = Истина Тогда
	ПроведениеРазрешено = Истина;
Иначе
	ПроведениеРазрешено = Ложь;
КонецЕсли;

// ✅ Хорошо
ПроведениеРазрешено = ПроверкаПройдена ИЛИ ПроверкиОтключены;
```

Тернарный оператор:

```bsl
// ❌ Плохо: пять строк ради выбора из двух значений
Если ДоставкаСрочная Тогда
	Срок = СрокСрочный;
Иначе
	Срок = СрокОбычный;
КонецЕсли;

// ✅ Хорошо
Срок = ?(ДоставкаСрочная, СрокСрочный, СрокОбычный);

// ❌ Плохо: вложенный тернарный оператор
Срок = ?(ДоставкаСрочная, СрокСрочный, ?(КлиентПостоянный, СрокЛьготный, СрокОбычный));
```

Двойное отрицание:

```bsl
// ❌ Плохо: какое условие здесь описано, предлагается разобрать самостоятельно
Если НЕ (НЕ ОстаткиКонтролируются ИЛИ НЕ ТоварНедостаточно) Тогда

// ✅ Хорошо
Если ОстаткиКонтролируются И ТоварНедостаточно Тогда
```

</details>

### 6.2 Циклы

- **6.2.1** Тело цикла — не длиннее 15–20 строк. Длинное тело выносится в методы.
- **6.2.2** Вложенные циклы подчиняются общему правилу 6.1.11: не больше трёх уровней.
- **6.2.3** Служебные операции цикла — изменение счётчика, `Продолжить`, `Прервать` — стоят в начале или в конце тела, а не в середине.
- **6.2.4** У длинного цикла один выход с очевидным условием. Много `Прервать`, разбросанных по телу, — знак, что цикл нужно переписать.

<details><summary>Примеры к 6.2</summary>

```bsl
// ❌ Плохо: фильтрация, поиск и заполнение перемешаны, выходы разбросаны по телу
Для Каждого ЦеныСтрока Из ЦеныТаблица Цикл
	Номенклатура = Справочники.Номенклатура.НайтиПоКоду(ЦеныСтрока.Код);
	Если Номенклатура.Пустая() Тогда
		Продолжить;
	КонецЕсли;
	НоваяСтрока = Документ.Товары.Добавить();
	НоваяСтрока.Номенклатура = Номенклатура;
	Если ЦеныСтрока.Цена = 0 Тогда
		Документ.Товары.Удалить(НоваяСтрока);
		Продолжить;
	КонецЕсли;
	НоваяСтрока.Цена = ЦеныСтрока.Цена;
	// ... ещё 30 строк
КонецЦикла;

// ✅ Хорошо: условие пропуска — в начале, работа — в отдельном методе
Для Каждого ЦеныСтрока Из ЦеныТаблица Цикл

	Если НЕ ЦенаЗагружаемая(ЦеныСтрока) Тогда
		Продолжить;
	КонецЕсли;

	ТоварыСтрокаДобавить(Документ, ЦеныСтрока);

КонецЦикла;
```

Один понятный выход вместо нескольких `Прервать`:

```bsl
// ❌ Плохо: выход из цикла спрятан в трёх местах
Для Каждого СкладыЭлемент Из Склады Цикл
	Если СкладыЭлемент.Закрыт Тогда
		Прервать;
	КонецЕсли;
	Остаток = пр_Остатки.Склад(СкладыЭлемент, Номенклатура);
	Если Остаток >= Потребность Тогда
		СкладНайденный = СкладыЭлемент;
		Прервать;
	КонецЕсли;
	Если Остаток = 0 И СкладыЭлемент.Основной Тогда
		Прервать;
	КонецЕсли;
КонецЦикла;

// ✅ Хорошо: поиск вынесен в функцию с одним понятным результатом
СкладНайденный = пр_Остатки.СкладСДостаточнымОстатком(Склады, Номенклатура, Потребность);
```

</details>

## Пояснения

### Основной сценарий — первым

Когда основной вариант идёт первым, код читается по главной линии, а не через череду исключительных ситуаций. Действие оказывается рядом с той точкой, где принято решение.

### Имена вместо условий

Выносить условие в функцию стоит даже тогда, когда оно используется один раз. Имя функции документирует смысл проверки прямо в коде — это лучше комментария, потому что код меняют, а комментарии часто забывают. Если условие повторяется, функция ещё и избавляет от параллельных правок.

### Скобки

Не полагайтесь на то, что вы — или читатель — помните приоритет `И`, `ИЛИ` и `НЕ`. Скобки делают намерение явным. Но если без скобок условие непонятно, возможно, его лучше разложить на части.

### Утвердительные условия

Во всём коде — единый стиль флагов: утвердительный. `Если ПроведениеРазрешено Тогда` читается легче, чем `Если НЕ ПроведениеЗапрещено Тогда`.

### Порядок вычисления

Платформа вычисляет логические выражения по сокращённой схеме: если результат ясен по первой части, вторая не вычисляется. Поэтому, когда порядок не влияет на смысл, первыми ставьте простые и дешёвые проверки, а тяжёлые — запросы, обращения к базе — последними.

```bsl
// ✅ Запрос выполнится, только если контроль остатков включён
Если ОстаткиКонтролируются И пр_Остатки.Недостаточно(Товары) Тогда
```

### Циклы

Короткий цикл видно целиком. У хорошо спроектированного цикла тело почти всегда укладывается в один-два вызова методов. Оценив, насколько проще читать такой код, вы редко будете писать циклы длиннее 15–20 строк.

Понимание цикла резко падает, когда вложенность больше трёх уровней. Если нужно глубже — вынесите внутренний цикл в метод. Осмысленные имена счётчиков и элементов (правило [5.5](./05_variables.md#правила)) подсказывают и назначение цикла, и то, с каким элементом идёт работа.
