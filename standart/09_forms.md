# 9. Формы и клиент-серверное взаимодействие

[Оглавление](./README.md) | Назад: [8. Запросы](./08_queries.md) | Далее: [10. Объекты метаданных](./10_metadata.md)

## Правила

### 9.1 Вызовы сервера

- **9.1.1** На одно действие пользователя — не больше одного обращения к серверу.
- **9.1.2** Для вызова сервера из формы используется внеконтекстный вызов (`&НаСервереБезКонтекста`, `&НаКлиентеНаСервереБезКонтекста`). Контекстный вызов (`&НаСервере`) — только когда без контекста формы действительно не обойтись.
- **9.1.3** Контекст формы не увеличивается без необходимости, особенно большими структурами данных: каждый контекстный вызов передаёт его на сервер и обратно.
- **9.1.4** Из событий, в которых контекстный вызов сервера запрещён, сервер с контекстом не вызывается (см. синтакс-помощник по событию). В событиях `ПриАктивизации*` сервер не вызывается совсем, даже без контекста; если без сервера не обойтись — через обработчик ожидания.
- **9.1.5** Параметры серверных методов передаются с `Знач` (см. [4.2.2](./04_methods.md#42-параметры)).
- **9.1.6** Перед перезаполнением большой коллекции на сервере она очищается на клиенте: незачем передавать на сервер данные, которые там сразу удалят.

<details><summary>Примеры к 9.1</summary>

Внеконтекстный вызов:

```bsl
// ❌ Плохо: контекст формы не нужен, но передаётся на сервер целиком
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
	ДоговорЗаполнитьНаСервере();
КонецПроцедуры

&НаСервере
Процедура ДоговорЗаполнитьНаСервере()
	Объект.Договор = пр_Договор.Основной(Объект.Контрагент, Объект.Организация);
КонецПроцедуры

// ✅ Хорошо: на сервер уходят только два значения
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
	Объект.Договор = ДоговорОсновной(Объект.Контрагент, Объект.Организация);
КонецПроцедуры

// Основной договор контрагента с организацией.
&НаСервереБезКонтекста
Функция ДоговорОсновной(Знач Контрагент, Знач Организация)

	Результат = пр_Договор.Основной(Контрагент, Организация);

	Возврат Результат;

КонецФункции
```

Активизация строки:

```bsl
// ❌ Плохо: вызов сервера при каждом перемещении по списку
&НаКлиенте
Процедура СписокПриАктивизацииСтроки(Элемент)
	ОстатокОбновитьНаСервере();
КонецПроцедуры

// ✅ Хорошо: обновление после паузы, когда пользователь остановился на строке
&НаКлиенте
Процедура СписокПриАктивизацииСтроки(Элемент)
	ПодключитьОбработчикОжидания("ОстатокОбновить", 0.2, Истина);
КонецПроцедуры

// Обновляет остаток по текущей строке списка.
&НаКлиенте
Процедура ОстатокОбновить()
	// ...
КонецПроцедуры
```

Очистка коллекции перед перезаполнением:

```bsl
// ✅ Хорошо: строки удаляются на клиенте, на сервер уходит пустая таблица
&НаКлиенте
Процедура ТоварыПерезаполнить(Команда)

	Объект.Товары.Очистить();
	ТоварыЗаполнитьНаСервере();

КонецПроцедуры
```

</details>

### 9.2 Модуль формы

- **9.2.1** Обработчики событий одного элемента формы располагаются вместе.
- **9.2.2** У каждого события свой обработчик. Если одинаковые действия нужны в событиях разных элементов, они выносятся в отдельный метод, который вызывается из обработчиков. Исключение — программный вызов обработчика, когда код выполняет действие, которое по логике должно его инициировать.
- **9.2.3** В форме хранимого объекта создаются оба обработчика — `ПриСозданииНаСервере` и `ПриЧтенииНаСервере` — и общий метод `ПриЧтенииСозданииНаСервере`, который вызывается из обоих. В нём выполняются действия, зависящие от данных объекта. Так форма правильно работает при стандартной команде «Перечитать».
- **9.2.4** Логика, не зависящая от формы, в модуле формы не пишется (см. [3.1.2](./03_modules.md#31-размещение-кода)).

<details><summary>Пример к 9.2.3</summary>

```bsl
// BSLLS:MissingParameterDescription-off - см. синтакс-помощник
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

	// Действия, не зависящие от данных объекта
	СписокВыбораСтатусовЗаполнить();

	// Для нового объекта ПриЧтенииНаСервере не вызывается
	Если Параметры.Ключ.Пустая() Тогда
		ПриЧтенииСозданииНаСервере();
	КонецЕсли;

КонецПроцедуры

&НаСервере
Процедура ПриЧтенииНаСервере(ТекущийОбъект)

	ПриЧтенииСозданииНаСервере();

КонецПроцедуры
// BSLLS:MissingParameterDescription-on

// Настройка формы по данным объекта: вызывается при создании и при каждом чтении.
&НаСервере
Процедура ПриЧтенииСозданииНаСервере()

	ДоставкаВидимостьУстановить();
	ТоварыИтогиРассчитать();

КонецПроцедуры
```

</details>

### 9.3 Прочее

- **9.3.1** Картинки в формах и командах — PNG с прозрачным фоном. BMP не используется: он некорректно отображается в веб-клиенте.
- **9.3.2** Формы, которые имеют смысл только в контексте другой формы, не открываются без владельца (через меню «Все функции» и т. п.). В таком случае показывается поясняющее сообщение.
- **9.3.3** Формы списка и выбора — разные формы. Исключение — когда это приводит к существенному дублированию кода: тогда одна форма с корректной обработкой режима выбора.

## Пояснения и рекомендации

### Почему вызовы сервера так важны

Каждый вызов сервера — это сетевое взаимодействие и сериализация данных. Для пользователя в веб-клиенте или на медленном канале лишний вызов заметен сразу. Контекстный вызов дополнительно передаёт все данные формы туда и обратно. Поэтому:

- собирайте на клиенте всё, что нужно для операции, и делайте один вызов;
- по умолчанию выбирайте `&НаСервереБезКонтекста`, а `&НаСервере` — только при необходимости;
- следите за размером формы: лишние реквизиты и элементы замедляют каждый контекстный вызов, а замеры производительности это не всегда показывают.

### Простые формы

Форма, перегруженная реквизитами и элементами, работает медленнее и сложнее для пользователя. Чем проще выглядит форма (при достаточном функционале), тем легче с ней работать.
