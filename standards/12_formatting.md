# 12. Форматирование

[↑ Оглавление](./README.md)

> Как выглядит код на экране: отступы, пустые строки, пробелы и переносы.

**Коротко**

- Форматирование — как у автоформатирования конфигуратора, отступы — табуляцией.
- Одна строка — один оператор, длина строки — до 120 символов.
- Пустая строка отделяет методы и логические блоки внутри метода, двух пустых строк подряд нет.
- При переносе продолжение начинается со знака операции; запятая между параметрами — в конце строки.

## Правила

### 12.1 Общие правила

- **12.1.1** Форматирование соответствует автоформатированию конфигуратора (выделить всё → «Форматировать»), в том числе в текстах запросов (см. [8. Запросы](./08_queries.md)). Типовые модули целиком не форматируются (см. [13.1.6](./13_typical_changes.md#131-общие-правила)).
- **12.1.2** Отступы в начале строк — только табуляцией.
- **12.1.3** Одна строка — один оператор: больше одной `;` в строке быть не может. Длинный оператор можно переносить на несколько строк.
- **12.1.4** Длина строки — не больше 120 символов, желательно — не больше 80.
- **12.1.5** Ключевые слова и имена пишутся так, как в синтакс-помощнике: `Если`, `КонецЕсли`, `Неопределено`. Строчными буквами или капсом — нельзя. Исключения: логические операторы пишутся как `И`, `ИЛИ`, `НЕ`, а ключевые слова языка запросов — капсом (`ВЫБРАТЬ`, `ГДЕ`), как их пишет конструктор.

<details><summary>Примеры к 12.1</summary>

```bsl
// ❌ Плохо: регистр как попало, два оператора в строке
если КлючДанных или Отказ тогда
	ТипСтрокой = неопределено; Возврат;
КОНЕЦЕСЛИ;

// ✅ Хорошо
Если КлючДанных ИЛИ Отказ Тогда
	ТипСтрокой = Неопределено;
	Возврат;
КонецЕсли;
```

</details>

### 12.2 Пустые строки

- **12.2.1** Методы отделяются друг от друга и от областей одной пустой строкой.
- **12.2.2** Логические блоки внутри метода отделяются одной пустой строкой.
- **12.2.3** Двух и более пустых строк подряд нет.
- **12.2.4** Модуль заканчивается переводом строки.

<details><summary>Пример к 12.2</summary>

```bsl
// Создаёт отчёты о розничных продажах — по одному на каждую пару «вид оплаты + дата».
//
// Параметры:
//	Продажи - ТаблицаЗначений - колонки: ВидОплаты, Дата, Номенклатура, Количество, Сумма.
//
Процедура Создать(Продажи) Экспорт

	Группы = Продажи.Скопировать(, "ВидОплаты, Дата");
	Группы.Свернуть("ВидОплаты, Дата");

	Для Каждого ГруппыСтрока Из Группы Цикл

		Отбор = Новый Структура("ВидОплаты, Дата", ГруппыСтрока.ВидОплаты, ГруппыСтрока.Дата);
		ГруппаПродажи = Продажи.Скопировать(Отбор);

		Отчет = Документы.ОтчетОРозничныхПродажах.СоздатьДокумент();
		Отчет.Дата = ГруппыСтрока.Дата;
		Отчет.ВидОплаты = ГруппыСтрока.ВидОплаты;
		Отчет.Товары.Загрузить(ГруппаПродажи);
		Отчет.Записать(РежимЗаписиДокумента.Проведение);

	КонецЦикла;

КонецПроцедуры
```

Строки, тесно связанные по смыслу (заполнение документа), идут подряд. Разные по смыслу блоки — подготовка групп, отбор данных, создание документа — разделены пустой строкой.

</details>

### 12.3 Пробелы

- **12.3.1** Знаки операций отделяются пробелами — по одному с каждой стороны.
- **12.3.2** После запятой — пробел, перед запятой — нет.
- **12.3.3** После открывающей и перед закрывающей скобкой пробелов нет.

<details><summary>Пример к 12.3</summary>

```bsl
// ❌ Плохо
Представление="Счет №"+СокрЛП(Номер)+" от "+Формат(Дата,"ДЛФ=Д");
Итог = СуммаРассчитать( Цена , Количество );

// ✅ Хорошо
Представление = "Счет №" + СокрЛП(Номер) + " от " + Формат(Дата, "ДЛФ=Д");
Итог = СуммаРассчитать(Цена, Количество);
```

</details>

### 12.4 Перенос строк

- **12.4.1** По перенесённой строке сразу видно, что она продолжает выражение: она начинается со знака операции, логического оператора или `|` ([стандарт 1С](https://its.1c.ru/db/v8std/content/444/hdoc)). Исключение — параметры методов (12.4.4).
- **12.4.2** Длинное арифметическое выражение или конкатенация: знак операции — в начале новой строки, отступ — одна табуляция. На одной строке может быть несколько операндов.
- **12.4.3** Многострочный текст: каждая строка продолжения начинается с `|`, отступ — одна табуляция от начала оператора.
- **12.4.4** Параметры в объявлении и вызове метода: запятая — **в конце строки**, как в стандарте 1С; продолжение — с отступом в одну табуляцию. Длинный вызов можно перенести сразу после открывающей скобки — тогда каждый параметр на своей строке.
- **12.4.5** Допускается и более удобный для чтения вариант — запятая **в начале** новой строки. В пределах модуля используется один вариант.
- **12.4.6** Сложное условие в `Если … ИначеЕсли`:
  - каждое элементарное условие может начинаться с новой строки;
  - `И`, `ИЛИ` ставятся в начале строки, а не в конце предыдущей;
  - отступ продолжения — одна табуляция от `Если`;
  - `Тогда` стоит на строке с последним условием;
  - группы условий выделяются скобками.

<details><summary>Примеры к 12.4</summary>

Арифметика и конкатенация:

```bsl
// ❌ Плохо: по концу первой строки не видно, что выражение продолжается
СуммаИтого = СуммаБезСкидки - СкидкаРучная - СкидкаАвтоматическая +
	СуммаДоставки;

// ✅ Хорошо
СуммаИтого = СуммаБезСкидки - СкидкаРучная - СкидкаАвтоматическая
	+ СуммаДоставки;
```

Многострочный текст:

```bsl
ЗапросТекст = "
	|ВЫБРАТЬ
	|	Склады.Ссылка КАК Ссылка
	|ИЗ
	|	Справочник.Склады КАК Склады";
```

Параметры — основной вариант, запятая в конце строки:

```bsl
Функция ДокументФормаОткрыть(ДокументСсылка, ФормаВладелец = Неопределено,
	ОткрытиеПараметры = Неопределено) Экспорт

ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена(),
	ПолучитьНавигационнуюСсылку(Заказ),
	Строка(Заказ),
	БиблиотекаКартинок.Информация32);

ПоказатьОповещениеПользователя(
	пр_ЗаказТексты.ОтгрузкаЗавершена(),
	ПолучитьНавигационнуюСсылку(Заказ),
	Строка(Заказ),
	БиблиотекаКартинок.Информация32);
```

Параметры — допустимый вариант, запятая в начале строки:

```bsl
Функция ДокументФормаОткрыть(ДокументСсылка
	, ФормаВладелец = Неопределено
	, ОткрытиеПараметры = Неопределено) Экспорт

ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена()
	, ПолучитьНавигационнуюСсылку(Заказ)
	, Строка(Заказ)
	, БиблиотекаКартинок.Информация32);
```

> Запятая в начале строки сразу показывает, что строка продолжает список параметров. Строку с параметром легко закомментировать при отладке или удалить, не трогая соседние, а при сравнении версий меняется одна строка вместо двух.

Выравнивание по первому параметру не используется: оно ломается при переименовании метода и требует пробелов.

```bsl
// ❌ Плохо
ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена(),
                               ПолучитьНавигационнуюСсылку(Заказ));
```

Сложное условие:

```bsl
Если (Заказ.Статус = Перечисления.СтатусыЗаказовКлиентов.Согласован
	ИЛИ Заказ.Статус = Перечисления.СтатусыЗаказовКлиентов.КОтгрузке)
	И Заказ.ДатаОтгрузки <= ТекущаяДатаСеанса() Тогда

	пр_Отгрузка.Создать(Заказ);

КонецЕсли;
```

</details>

### 12.5 Коллекции и порядок

- **12.5.1** Структура с четырьмя и более ключами не создаётся конструктором со списком ключей: такую строку трудно читать и дорабатывать. Ключи добавляются через `Вставить()`.
- **12.5.2** Там, где порядок не важен для логики — ключи структуры, перечни имён, строковые списки, — элементы идут по алфавиту, и новый элемент сразу встаёт на своё место.

<details><summary>Пример к 12.5</summary>

```bsl
// ❌ Плохо: ключи и значения приходится сопоставлять по позиции
ДоговорДанные = Новый Структура("Наименование, Организация, ВидДоговора, ВалютаРасчетов, Контрагент",
	ДоговорНаименование, Организация, Перечисления.ВидыДоговоров.СПокупателем, ВалютаУчета, Контрагент);

// ✅ Хорошо: ключи по алфавиту, каждое значение рядом со своим ключом
ДоговорДанные = Новый Структура;
ДоговорДанные.Вставить("ВалютаРасчетов", ВалютаУчета);
ДоговорДанные.Вставить("ВидДоговора", Перечисления.ВидыДоговоров.СПокупателем);
ДоговорДанные.Вставить("Контрагент", Контрагент);
ДоговорДанные.Вставить("Наименование", ДоговорНаименование);
ДоговорДанные.Вставить("Организация", Организация);
```

</details>

## Пояснения

### Один оператор — одна строка

Несколько операторов на строке экономят место, но:

- прячут сложность: сложный код выглядит простым;
- заставляют читать каждую строку целиком, а не скользить взглядом по левому краю;
- мешают отладке: отладчик выполняет строку целиком;
- усложняют правку и сравнение версий.

```bsl
// ❌ Плохо
Если Элементы.Описание.ТолькоПросмотр Тогда Элементы.Описание.ТолькоПросмотр = Ложь; Иначе Элементы.Описание.ТолькоПросмотр = Истина; КонецЕсли;

// ✅ Хорошо: разнесли по строкам — и стало видно, что ветвление не нужно
Элементы.Описание.ТолькоПросмотр = НЕ Элементы.Описание.ТолькоПросмотр;
```

Длинные цепочки вызовов — та же история: их трудно читать и невозможно отлаживать по шагам.

```bsl
// ❌ Плохо
Возврат Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Ссылка");
```

### Вертикальное разделение и сжатие

Код читается сверху вниз. Каждая группа строк — законченная мысль, пустая строка — знак, что начинается следующая. Тесно связанные строки, наоборот, идут подряд. Взгляд цепляется за первые строки блоков, поэтому хорошо разбитый на блоки код можно «пролистать» глазами.

### Связанные методы — рядом

Методы, которые вызываются из метода верхнего уровня, стоят сразу после него и в порядке вызова. Чем сильнее связь, тем ближе методы. Обработчик оповещения — сразу после метода, который его вызывает.

### Горизонтальное выравнивание

Выравнивать однотипные присваивания можно — иногда это подчёркивает их связь. Выравнивают табуляцией. Но не делайте этого механически: при переименовании выравнивание ломается, а иногда отвлекает больше, чем помогает. Цель — читаемость, а не соблюдение формы.
