# 7. Исключения и транзакции

[↑ Оглавление](./README.md)

> Когда перехватывать ошибки, как их обрабатывать и как правильно оформлять транзакции.

**Коротко**

- `Попытка` — только для действительно небезопасных операций: файлы, внешние сервисы, разбор чужих данных.
- Ошибка никогда не «проглатывается»: о ней сообщают пользователю или передают выше. В коде без пользователя её пишут в журнал регистрации и учитывают в итоге.
- Транзакция начинается и завершается в одном методе. В блоке `Исключение` первым идёт `ОтменитьТранзакцию()`.

## Правила

### 7.1 Попытка и исключения

- **7.1.1** `Попытка` используется только там, где ошибка возможна по причинам, не зависящим от качества кода: работа с файлами, внешними источниками и сервисами, разбор данных с негарантированной структурой.
- **7.1.2** `Попытка` не используется, чтобы проверить тип, наличие реквизита или метода, привести значение к типу или заменить условный оператор.
- **7.1.3** Первым оператором блока `Исключение` получается информация об ошибке: `Информация = ИнформацияОбОшибке();`. Так она точно не потеряется, а отлаживать проще. Исключение — блок с транзакцией: там первым вызывается `ОтменитьТранзакцию()` (7.2.2).
- **7.1.4** Блок `Исключение` либо сообщает об ошибке пользователю, либо передаёт её выше через `ВызватьИсключение`. Пустой блок («проглатывание» ошибки) запрещён. Блок, который только пишет в журнал регистрации, приравнивается к пустому.

  Исключение — код, который выполняется без пользователя и обрабатывает набор элементов: регламентные и фоновые задания, обмены, обработчики обновления. Там ошибка одного элемента пишется в журнал регистрации, и обработка продолжается ([стандарт 1С](https://its.1c.ru/db/v8std/content/499/hdoc)). Но итог не теряется: ошибки подсчитываются, и в конце метод вызывает исключение или сохраняет состояние, по которому сбой заметят.
- **7.1.5** Исключение передаёт ошибку наверх и прекращает выполнение. По его тексту понятно, где и почему возникла ошибка.
- **7.1.6** `ВызватьИсключение` без текста пишется только внутри блока `Исключение` — чтобы передать перехваченную ошибку выше без изменений. Вне этого блока оператор без текста не компилируется. Если пользователю уже показано сообщение с привязкой к полю, в обработчике события устанавливается `Отказ`; вне обработчика вызывается исключение с текстом.
- **7.1.7** Ошибка представляется методами объекта `ОбработкаОшибок`:
  - `ОбработкаОшибок.КраткоеПредставлениеОшибки(Информация)` — для пользователя;
  - `ОбработкаОшибок.ПодробноеПредставлениеОшибки(Информация)` — для журнала регистрации.

  `ОписаниеОшибки()` для этого не используется. Прежние варианты — в [Устаревших правилах](./99_deprecated.md).

Проверка вместо `Попытка`:

```bsl
// ❌ Плохо: исключение как способ проверить наличие реквизита
Попытка
	Организация = Объект.Организация;
Исключение
	Организация = пр_Организация.Основная();
КонецПопытки;

// ✅ Хорошо
Если ОбщегоНазначения.ЕстьРеквизитОбъекта("Организация", Объект.Метаданные()) Тогда
	Организация = Объект.Организация;
Иначе
	Организация = пр_Организация.Основная();
КонецЕсли;
```

Приведение типа без `Попытка`:

```bsl
// ❌ Плохо
Попытка
	ДнейКоличество = Число(ЗначениеСтрока);
Исключение
	ДнейКоличество = 0;
КонецПопытки;

// ✅ Хорошо: строка, которая не является числом, превратится в 0
ЧислоОписание = Новый ОписаниеТипов("Число");
ДнейКоличество = ЧислоОписание.ПривестиЗначение(ЗначениеСтрока);
```

«Проглатывание» ошибки:

```bsl
// ❌ Плохо: ошибка исчезает бесследно
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
КонецПопытки;

// ❌ Тоже плохо: журнал регистрации оперативно никто не читает
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
	ЗаписьЖурналаРегистрации("Загрузка прайса", УровеньЖурналаРегистрации.Ошибка);
КонецПопытки;
```

Правильная обработка:

```bsl
// ✅ Хорошо: подробности — в журнал, понятный текст — выше
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
	Информация = ИнформацияОбОшибке();
	ЗаписьЖурналаРегистрации(пр_ПрайсТекстыКлиентСервер.ЗагрузкаСобытие(), УровеньЖурналаРегистрации.Ошибка, , ,
		ОбработкаОшибок.ПодробноеПредставлениеОшибки(Информация));
	ВызватьИсключение СтрШаблон(пр_ПрайсТекстыКлиентСервер.ФайлЧтениеОшибка(), ИмяФайла,
		ОбработкаОшибок.КраткоеПредставлениеОшибки(Информация));
КонецПопытки;
```

Ошибка одного элемента в регламентном задании (исключение из 7.1.4):

```bsl
// ✅ Допустимо: ошибка одного заказа не останавливает выгрузку остальных, но учитывается в итоге
ОшибокКоличество = 0;
Для Каждого ЗаказыЭлемент Из Заказы Цикл

	Попытка
		пр_ОбменСайт.ЗаказВыгрузить(ЗаказыЭлемент);
	Исключение
		Информация = ИнформацияОбОшибке();
		ОшибокКоличество = ОшибокКоличество + 1;
		ЗаписьЖурналаРегистрации(пр_ОбменСайтТекстыКлиентСервер.ВыгрузкаСобытие(), УровеньЖурналаРегистрации.Ошибка, ,
			ЗаказыЭлемент, ОбработкаОшибок.ПодробноеПредставлениеОшибки(Информация));
	КонецПопытки;

КонецЦикла;

Если ОшибокКоличество > 0 Тогда
	ВызватьИсключение СтрШаблон(пр_ОбменСайтТекстыКлиентСервер.ВыгрузкаОшибки(), ОшибокКоличество);
КонецЕсли;
```

`ВызватьИсключение` и сообщение с привязкой к полю (7.1.6):

```bsl
// ❌ Не компилируется: вне блока Исключение оператору нужен текст

	ТекстОшибки = пр_ЗаказКлиентаТекстыКлиентСервер.СкладЗаполнениеОбязательно();
	ОбщегоНазначения.СообщитьПользователю(ТекстОшибки, , "Склад", "Объект");

Если НЕ ЗначениеЗаполнено(Склад) Тогда
	ТекстОшибки = пр_ЗаказКлиентаТекстыКлиентСервер.СкладЗаполнениеОбязательно();

КонецЕсли;

// ✅ Хорошо: вне обработчика события — исключение с текстом
Если НЕ ЗначениеЗаполнено(Склад) Тогда
	ВызватьИсключение пр_ЗаказКлиентаТекстыКлиентСервер.СкладЗаполнениеОбязательно();
КонецЕсли;
```

### 7.2 Транзакции

- **7.2.1** Транзакция начинается и завершается в одном методе.
- **7.2.2** Явная транзакция оформляется по [стандарту 1С](https://its.1c.ru/db/v8std/content/783/hdoc):
  - `НачатьТранзакцию()` стоит непосредственно перед `Попытка`;
  - последний оператор блока `Попытка` — `ЗафиксироватьТранзакцию()`;
  - в блоке `Исключение` **первым** вызывается `ОтменитьТранзакцию()`, затем ошибка пишется в журнал регистрации и передаётся выше через `ВызватьИсключение`.
- **7.2.3** Транзакцию, которую начала платформа (например, при записи объекта), отменяют только через `Отказ = Истина` в обработчике события.
- **7.2.4** Вложенные транзакции платформа поддерживает только на уровне кода, а не базы данных. На каждом пути выполнения каждому `НачатьТранзакцию()` соответствует ровно один `ЗафиксироватьТранзакцию()` или `ОтменитьТранзакцию()`. Одна отмена на любом уровне отменяет всю транзакцию.
- **7.2.5** После ошибки базы данных внутри транзакции любое следующее обращение к базе тоже завершится ошибкой («В данной транзакции уже происходили ошибки»), пока не вызван `ОтменитьТранзакцию()`. Поэтому данные для сообщения об ошибке читаются заранее или уже после отмены транзакции.

<details><summary>Примеры к 7.2</summary>

Явная транзакция:

```bsl
// Переносит резерв товаров со старого заказа на новый.
//
// Параметры:
//	ЗаказИсточник - ДокументСсылка.ЗаказКлиента - заказ, с которого снимается резерв.
//	ЗаказПриемник - ДокументСсылка.ЗаказКлиента - заказ, на который переносится резерв.
//
Процедура Перенести(ЗаказИсточник, ЗаказПриемник) Экспорт

	НачатьТранзакцию();
	Попытка

		РезервыЗаблокировать(ЗаказИсточник, ЗаказПриемник);
		РезервыТаблица = пр_Резерв.ЗаказТовары(ЗаказИсточник);
		пр_Резерв.Снять(ЗаказИсточник);
		пр_Резерв.Установить(ЗаказПриемник, РезервыТаблица);

		ЗафиксироватьТранзакцию();

	Исключение

		ОтменитьТранзакцию();
		ЗаписьЖурналаРегистрации(пр_РезервТекстыКлиентСервер.ПереносСобытие(), УровеньЖурналаРегистрации.Ошибка, , ,
			ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
		ВызватьИсключение;

	КонецПопытки;

КонецПроцедуры
```

Отмена транзакции платформы (7.2.3):

```bsl
// ❌ Плохо: вызов исключения ради отмены записи
Процедура ПередЗаписью(Отказ)
	Если Сумма > ЛимитСумма Тогда
		ВызватьИсключение пр_ЗаявкаТекстыКлиентСервер.ЛимитПревышен();
	КонецЕсли;
КонецПроцедуры

// ✅ Хорошо: сообщение и Отказ
Процедура ПередЗаписью(Отказ)
	Если Сумма > ЛимитСумма Тогда
		ТекстОшибки = пр_ЗаявкаТекстыКлиентСервер.ЛимитПревышен();
		ОбщегоНазначения.СообщитьПользователю(ТекстОшибки, ЭтотОбъект, "Сумма", , Отказ);
	КонецЕсли;
КонецПроцедуры
```

## Пояснения

### `Попытка` — крайняя мера

**Если без `Попытка` можно обойтись, без неё обходятся** ([стандарт 1С](https://its.1c.ru/db/v8std/content/499/hdoc)). Лишние попытки:

- усложняют отладку: ошибка перехватывается далеко от места, где возникла;
- ухудшают читаемость: непонятно, какую ошибку ожидал автор;
- прячут настоящие ошибки среди «ожидаемых».

Механизм исключений нужен для одного: выполнить небезопасное действие так, чтобы ошибку можно было обработать.

### Почему журнал регистрации — не обработка

Журнал регистрации оперативно не читают, а иногда не читают вовсе. Ошибка, записанная только туда, для пользователя не существует: он уверен, что всё прошло успешно. Важные ошибки показывают сразу или передают выше, а журнал — дополнительный источник подробностей для разработчика.

Иначе обстоит дело там, где пользователя нет: в регламентных и фоновых заданиях, обменах, обработчиках обновления. Сообщать некому, а ошибка одного элемента не должна останавливать обработку остальных. Здесь запись в журнал — штатная обработка, но только вместе с итогом: задание, которое молча пропустило половину элементов и завершилось успешно, ничем не лучше пустого блока `Исключение`.

### Почему отмена транзакции — первой

Пока транзакция не отменена, любое обращение к базе после ошибки снова падает (7.2.5). Если в блоке `Исключение` сначала прочитать что-то из базы для сообщения, вместо исходной ошибки пользователь увидит «В данной транзакции уже происходили ошибки». Отмена первой строкой исключает такую ситуацию.
