# 8. Запросы

[↑ Оглавление](./README.md)

> Как оформлять тексты запросов и как писать запросы, которые не тормозят.

**Коротко**

- Оформление — как у конструктора запроса: с новой строки, табуляцией, с псевдонимами.
- Текст запроса — в отдельной функции.
- Подзапросы и виртуальные таблицы не соединяем: сначала кладём их во временную таблицу.
- Константы — прямо в тексте, отборы виртуальных таблиц — в их параметрах.

## Правила

### 8.1 Оформление

- **8.1.1** Ориентир оформления — результат работы конструктора запроса.
- **8.1.2** Текст запроса начинается с новой строки. Отступы внутри — табуляцией.
- **8.1.3** Текст передаётся сразу в `Новый Запрос(...)`. Отдельное присваивание `Запрос.Текст` — только когда текст собирается динамически.
- **8.1.4** Запрос не пишется в одну строку.
- **8.1.5** Псевдонимы полей и таблиц — такие, какие расставляет конструктор, в том числе совпадающие с именем поля. Тогда правка в конструкторе не меняет текст лишний раз, а сравнение версий показывает только настоящие изменения.
- **8.1.6** Длинным именам таблиц даются короткие осмысленные псевдонимы.
- **8.1.7** Имена временных таблиц начинаются с `Таблица`: `ТаблицаОстатки`, `ТаблицаЗаказы`.
- **8.1.8** Текст запроса оформляется отдельной функцией. Метод, который работает с результатом, становится короче, а запрос отделяется от обработки.
- **8.1.9** Сложный или динамический запрос (больше пяти выборок, временных таблиц или соединений) начинается с комментария: что делает запрос и как примерно выполняется.
- **8.1.10** Комментарии в тексте запроса сохраняются при работе в конструкторе: конструктор их удаляет, и их нужно вернуть.

<details><summary>Примеры к 8.1</summary>

```bsl
// ❌ Плохо: текст начинается на строке конструктора, пробелы вместо табуляции, нет псевдонимов
Запрос = Новый Запрос("ВЫБРАТЬ
|    Ссылка,
|    Код
|ИЗ
|    Справочник.Валюты");

// ✅ Хорошо
Запрос = Новый Запрос("
	|ВЫБРАТЬ
	|	Валюты.Ссылка КАК Ссылка,
	|	Валюты.Код КАК Код
	|ИЗ
	|	Справочник.Валюты КАК Валюты
	|");
```

Короткие псевдонимы и имена временных таблиц:

```bsl
// ❌ Плохо: длинный псевдоним, который предложил конструктор, и безликая временная таблица
|ПОМЕСТИТЬ ВТ
|ИЗ
|	РегистрСведений.БазаРаспределенияЗатратМеждународныйУчет.СрезПоследних КАК БазаРаспределенияЗатратМеждународныйУчетСрезПоследних

// ✅ Хорошо
|ПОМЕСТИТЬ ТаблицаРаспределениеНастройки
|ИЗ
|	РегистрСведений.БазаРаспределенияЗатратМеждународныйУчет.СрезПоследних КАК РаспределениеНастройки
```

Текст запроса в отдельной функции:

```bsl
// Остатки товаров на складе.
//
// Параметры:
//	Склад - СправочникСсылка.Склады - склад.
//
// Возвращаемое значение:
//	ТаблицаЗначений - колонки: Номенклатура, Количество.
//
Функция Остатки(Склад) Экспорт

	Запрос = Новый Запрос(ОстаткиЗапросТекст());
	Запрос.УстановитьПараметр("Склад", Склад);

	Результат = Запрос.Выполнить().Выгрузить();

	Возврат Результат;

КонецФункции

// Текст запроса остатков товаров на складе.
Функция ОстаткиЗапросТекст()

	Результат = "
	|ВЫБРАТЬ
	|	Остатки.Номенклатура КАК Номенклатура,
	|	Остатки.КоличествоОстаток КАК Количество
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
	|";

	Возврат Результат;

КонецФункции
```

Комментарий к сложному запросу:

```bsl
	Результат = "
	|// Сверка документов поступления с данными поставщика.
	|//
	|// Шаги (каждый следующий работает с тем, что не попало в предыдущие):
	|//	1. ТаблицаЧерновики - документы есть, но не проведены
	|//	2. ТаблицаСовпадения - состав совпадает по номенклатуре и количеству
	|//	3. ТаблицаРасхождения - документ найден, состав отличается
	|//	4. ТаблицаЛишниеУНас - документы, которых нет у поставщика
	|//	5. ТаблицаЛишниеУПоставщика - данные поставщика без документа
	|//
	|// Псевдонимы: Поступления - наши документы, Поставщик - загруженные данные
	|
	|ВЫБРАТЬ
	|	// ...
	|";
```

### 8.2 Содержание

- **8.2.1** Константы — пустые даты и ссылки, предопределённые элементы, значения перечислений — пишутся прямо в тексте запроса: `ЗНАЧЕНИЕ(...)`, `ДАТАВРЕМЯ(1, 1, 1)`. Параметры для них не нужны.
- **8.2.2** К реквизитам поля составного типа обращаемся через `ВЫРАЗИТЬ` с явным типом. Иначе платформа неявно соединит все таблицы, на которые может ссылаться поле.
- **8.2.3** Результаты объединяются через `ОБЪЕДИНИТЬ ВСЕ`. `ОБЪЕДИНИТЬ` — только когда удаление одинаковых строк действительно нужно по смыслу.
- **8.2.4** Соединения с подзапросами, в том числе с виртуальными таблицами, запрещены ([стандарт 1С](https://its.1c.ru/db/metod8dev/content/5842/hdoc)): подзапрос сначала помещается во временную таблицу. Исключение — места, где временные таблицы недоступны (RLS, динамические списки); такие запросы обязательно проходят внимательное ревью.
- **8.2.5** Отборы виртуальных таблиц задаются в их параметрах, а не в секции `ГДЕ`.
- **8.2.6** `ДЛЯ ИЗМЕНЕНИЯ` работает только в автоматическом режиме блокировок. В управляемом режиме используется `БлокировкаДанных`.
- **8.2.7** Прежде чем перебирать результат, проверяем, что он не пустой: `Результат.Пустой()`.

<details><summary>Примеры к 8.2</summary>

Константы в тексте запроса:

```bsl
// ❌ Плохо: константы передаются параметрами
|ГДЕ
|	Заказы.Статус = &СтатусСогласован
|	И Заказы.ДатаОтгрузки <> &ПустаяДата

// ✅ Хорошо
|ГДЕ
|	Заказы.Статус = ЗНАЧЕНИЕ(Перечисление.СтатусыЗаказовКлиентов.Согласован)
|	И Заказы.ДатаОтгрузки <> ДАТАВРЕМЯ(1, 1, 1)
```

Поле составного типа:

```bsl
// ❌ Плохо: неявные соединения со всеми таблицами типов поля Регистратор
|ВЫБРАТЬ
|	Движения.Регистратор.Контрагент КАК Контрагент

// ✅ Хорошо
|ВЫБРАТЬ
|	ВЫРАЗИТЬ(Движения.Регистратор КАК Документ.РеализацияТоваровУслуг).Контрагент КАК Контрагент
```

Отбор в параметрах виртуальной таблицы:

```bsl
// ❌ Плохо: СУБД сначала посчитает остатки по всем складам, а потом отберёт нужный
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
|ГДЕ
|	Остатки.Склад = &Склад

// ✅ Хорошо: остатки считаются только по нужному складу
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
```

Соединение с виртуальной таблицей:

```bsl
// ❌ Плохо: соединение с виртуальной таблицей — с подзапросом на уровне СУБД
|ВЫБРАТЬ
|	Товары.Номенклатура КАК Номенклатура,
|	ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|	Документ.ЗаказКлиента.Товары КАК Товары
|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
|		ПО Товары.Номенклатура = Остатки.Номенклатура

// ✅ Хорошо: товары и остатки — во временных таблицах, отбор остатков — в параметрах
|ВЫБРАТЬ
|	Товары.Номенклатура КАК Номенклатура
|ПОМЕСТИТЬ ТаблицаТовары
|ИЗ
|	Документ.ЗаказКлиента.Товары КАК Товары
|ГДЕ
|	Товары.Ссылка = &Заказ
|
|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура
|;
|
|////////////////////////////////////////////////////////////////////////////////
|ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК КоличествоОстаток
|ПОМЕСТИТЬ ТаблицаОстатки
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(,
|		Номенклатура В
|			(ВЫБРАТЬ
|				ТаблицаТовары.Номенклатура
|			ИЗ
|				ТаблицаТовары КАК ТаблицаТовары)) КАК Остатки
|
|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура
|;
|
|////////////////////////////////////////////////////////////////////////////////
|ВЫБРАТЬ
|	Товары.Номенклатура КАК Номенклатура,
|	ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|	ТаблицаТовары КАК Товары
|		ЛЕВОЕ СОЕДИНЕНИЕ ТаблицаОстатки КАК Остатки
|		ПО Товары.Номенклатура = Остатки.Номенклатура
```

Блокировка в управляемом режиме:

```bsl
// ❌ Плохо: в управляемом режиме ДЛЯ ИЗМЕНЕНИЯ ничего не блокирует
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
|ДЛЯ ИЗМЕНЕНИЯ

// ✅ Хорошо: явная управляемая блокировка до чтения остатков
Блокировка = Новый БлокировкаДанных;
ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
ЭлементБлокировки.УстановитьЗначение("Склад", Склад);
ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
Блокировка.Заблокировать();
```


## Чек-лист проверки запроса

Основные требования к запросам — в [методике 1С](https://its.1c.ru/db/metod8dev/content/5842/hdoc). Ниже — вопросы, которые стоит задать себе, проектируя запрос.

**Параметры**

- [ ] Параметры вычислены до выполнения запроса, а не внутри его текста?

**Виртуальные таблицы**

- [ ] Отборы перенесены в параметры виртуальной таблицы — настолько, насколько возможно?
- [ ] Для `СрезПоследних` не передаётся период, если нужны текущие данные? Тогда используются текущие итоги (если они включены у регистра).
- [ ] Период оборотов не кратен месяцу или периодичность меньше месяца? Тогда таблица итогов не используется, и, возможно, быстрее выбрать из физической таблицы движений.
- [ ] У регистра остатков нужны только обороты? Таблица оборотов у него не хранится — возможно, лучше выбрать из физической таблицы.
- [ ] Обороты выбираются без начальной даты? Без других отборов выборка растёт вместе с таблицей итогов, а после свёртки базы результат может измениться.

**`ПОДОБНО`**

- [ ] Шаблон начинается с `%`? Тогда индекс не используется. То же касается отбора «Содержит» в динамическом списке. Такие шаблоны применяйте осознанно.

**Соединения**

- [ ] Соединений немного? Платформа добавляет свои, неявные (составные типы, RLS, представления), и реальное их число больше видимого. Ориентир: если явных соединений больше 7–8, подумайте, как упростить запрос.
- [ ] Можно ли заменить соединение объединением? Объединение для СУБД дешевле.
- [ ] Нет полных соединений? Обычно их можно заменить объединением.
- [ ] Нет соединений с виртуальными таблицами и подзапросами (8.2.4)? Если сомневаетесь, выгодна ли временная таблица, посмотрите план запроса или спросите ведущего разработчика.
- [ ] Нет подзапросов в условии соединения или в `ГДЕ`, которые можно заменить соединением с временной таблицей?

**Индексы**

- [ ] Условия используют поля индекса без пропусков и в порядке их следования? Иногда стоит добавить условие на пропущенное поле или перестроить индекс — но проверьте, не пострадают ли другие запросы к таблице.
- [ ] Временные таблицы проиндексированы по полям соединений **там, где индекс действительно будет использован**? При соединении hash match или если временная таблица стоит слева в nested loop, индекс не нужен, и ресурсы на индексацию тратятся впустую.

**Временные таблицы**

- [ ] Нет лишних временных таблиц? Каждая нагружает `tempdb` СУБД.

**Составной тип**

- [ ] Нет обращения через точку к полям составного типа без `ВЫРАЗИТЬ`?
- [ ] `ВЫРАЗИТЬ(...)` в `ГДЕ` и `ПО` без обращения к реквизиту через точку может привести к сканированию таблицы.
- [ ] Тип проверяется через `ССЫЛКА` или `ТИПЗНАЧЕНИЯ()`, а не обращением через точку?

**Условие `ИЛИ`**

- [ ] `ИЛИ` по одному полю — индекс используется, проблем нет.
- [ ] `ИЛИ` по разным индексированным полям — индекс может использоваться, а может и нет: зависит от размера таблицы, селективности и статистики. Смотрите план запроса. Часто лучше заменить на `ОБЪЕДИНИТЬ ВСЕ`.
- [ ] `ИЛИ` по разным полям, из которых хотя бы одно без индекса, — гарантированное сканирование таблицы.

```bsl
// ❌ Возможно сканирование таблицы
|ГДЕ
|	Реализация.Номер = &Номер
|	ИЛИ Реализация.Контрагент = &Контрагент

// ✅ Каждая часть использует свой индекс
|ВЫБРАТЬ
|	Реализация.Ссылка КАК Ссылка
|ИЗ
|	Документ.РеализацияТоваровУслуг КАК Реализация
|ГДЕ
|	Реализация.Номер = &Номер
|
|ОБЪЕДИНИТЬ ВСЕ
|
|ВЫБРАТЬ
|	Реализация.Ссылка КАК Ссылка
|ИЗ
|	Документ.РеализацияТоваровУслуг КАК Реализация
|ГДЕ
|	Реализация.Контрагент = &Контрагент
```

> С `ОБЪЕДИНИТЬ ВСЕ` один и тот же документ может попасть в результат дважды. Если это важно, используйте `ОБЪЕДИНИТЬ` — правило 8.2.3 это разрешает, когда удаление дублей нужно по смыслу.
