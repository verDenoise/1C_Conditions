# 12. Форматирование

[Оглавление](./README.md) | Назад: [11. Комментарии и описания](./11_comments.md) | Далее: [13. Изменение типовой конфигурации](./13_typical_changes.md)

## Правила

### 12.1 Общие правила

- **12.1.1** Форматирование соответствует автоформатированию конфигуратора (выделить всё → «Форматировать»). Это относится и к текстам запросов (см. [8. Запросы](./08_queries.md)). Типовые модули целиком не форматируются (см. [13.1.6](./13_typical_changes.md#131-общие-правила)).
- **12.1.2** Отступы в начале строк — только табуляцией. Пробелы для отступов запрещены.
- **12.1.3** Одна строка — один оператор. Больше одной `;` в строке запрещено. Перенос длинного оператора на несколько строк разрешён.
- **12.1.4** Длина строки — не больше 120 символов, желательно не больше 80.
- **12.1.5** Ключевые слова и имена пишутся так, как в синтакс-помощнике: `Если`, `КонецЕсли`, `Неопределено`. Написание строчными буквами или капсом запрещено. Исключение — ключевые слова языка запросов, которые пишутся капсом (`ВЫБРАТЬ`, `ГДЕ`), как их пишет конструктор.

### 12.2 Пустые строки

- **12.2.1** Методы отделяются друг от друга и от областей одной пустой строкой.
- **12.2.2** Внутри метода логические блоки отделяются одной пустой строкой.
- **12.2.3** Две и более пустые строки подряд запрещены.
- **12.2.4** Модуль заканчивается переводом строки.

<details><summary>Пример к 12.2</summary>

```bsl
// Создаёт документы отчёта о продажах по группам «вид оплаты + дата».
//
// Параметры:
//	Продажи - ТаблицаЗначений - колонки: ВидОплаты, Дата, Сумма.
//
Процедура Создать(Продажи) Экспорт

	Группы = Продажи.Скопировать(, "ВидОплаты, Дата");
	Группы.Свернуть("ВидОплаты, Дата");

	Для Каждого ГруппыСтрока Из Группы Цикл

		Отбор = Новый Структура("ВидОплаты, Дата", ГруппыСтрока.ВидОплаты, ГруппыСтрока.Дата);
		ГруппаПродажи = Продажи.Скопировать(Отбор);

		Отчет = Документы.ОтчетОРозничныхПродажах.СоздатьДокумент();
		Отчет.Дата = ГруппыСтрока.Дата;
		Отчет.ВидОплаты = ГруппыСтрока.ВидОплаты;
		Отчет.Товары.Загрузить(ГруппаПродажи);
		Отчет.Записать(РежимЗаписиДокумента.Проведение);

	КонецЦикла;

КонецПроцедуры
```

Строки, тесно связанные по смыслу (заполнение реквизитов документа), идут подряд. Разные по смыслу блоки (подготовка групп, отбор данных группы, создание документа) разделены пустой строкой.

</details>

### 12.3 Пробелы

- **12.3.1** Операнды отделяются от знаков операций пробелами — по одному с каждой стороны.
- **12.3.2** После запятой ставится пробел (в том числе между параметрами), перед запятой — нет.
- **12.3.3** После открывающей и перед закрывающей скобкой пробел не ставится.

<details><summary>Пример к 12.3</summary>

```bsl
// ❌ Плохо
Представление="Счет №"+СокрЛП(Номер)+" от "+Формат(Дата,"ДЛФ=Д");
Итог = СуммаРассчитать( Цена , Количество );

// ✅ Хорошо
Представление = "Счет №" + СокрЛП(Номер) + " от " + Формат(Дата, "ДЛФ=Д");
Итог = СуммаРассчитать(Цена, Количество);
```

</details>

### 12.4 Перенос строк

- **12.4.1** Перенесённая строка должна явно показывать, что она продолжает выражение: начинается со знака операции, логического оператора или символа `|` ([стандарт 1С](https://its.1c.ru/db/v8std/content/444/hdoc)). Исключение — параметры методов (правило 12.4.4).
- **12.4.2** Длинные арифметические выражения и конкатенация: знак операции — в начале новой строки, отступ — одна табуляция. На одной строке может быть несколько операндов.
- **12.4.3** Многострочный текст: каждая строка продолжения начинается с `|` и выравнивается по первому символу оператора плюс одна табуляция.
- **12.4.4** Параметры в объявлении и вызове метода: запятая — **в конце строки**, как в стандарте 1С; продолжение — с отступом в одну табуляцию. Длинный вызов можно начать переносом сразу после открывающей скобки, тогда каждый параметр — на своей строке.
- **12.4.5** Допустимый вариант, более удобный для чтения и правки, — запятая **в начале** новой строки. Выбранный вариант соблюдается во всём модуле.
- **12.4.6** Сложные условия в `Если … ИначеЕсли`:
  - каждое элементарное условие может начинаться с новой строки;
  - логический оператор (`И`, `ИЛИ`) ставится в начале строки, а не в конце предыдущей;
  - отступ продолжения — одна табуляция от `Если`;
  - `Тогда` пишется на строке с последним условием;
  - группы условий выделяются скобками.

<details><summary>Примеры к 12.4</summary>

Арифметика и конкатенация:

```bsl
// ❌ Плохо: по концу первой строки не видно, что выражение продолжается
СуммаИтого = СуммаБезСкидки - СкидкаРучная - СкидкаАвтоматическая +
	СуммаДоставки;

// ✅ Хорошо
СуммаИтого = СуммаБезСкидки - СкидкаРучная - СкидкаАвтоматическая
	+ СуммаДоставки;
```

Многострочный текст:

```bsl
ЗапросТекст = "
	|ВЫБРАТЬ
	|	Склады.Ссылка КАК Ссылка
	|ИЗ
	|	Справочник.Склады КАК Склады";
```

Параметры метода — основной вариант (запятая в конце):

```bsl
Функция ДокументФормаОткрыть(ДокументСсылка, ФормаВладелец = Неопределено,
	ОткрытиеПараметры = Неопределено) Экспорт

ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена(),
	ПолучитьНавигационнуюСсылку(Заказ),
	Строка(Заказ),
	БиблиотекаКартинок.Информация32);

ПоказатьОповещениеПользователя(
	пр_ЗаказТексты.ОтгрузкаЗавершена(),
	ПолучитьНавигационнуюСсылку(Заказ),
	Строка(Заказ),
	БиблиотекаКартинок.Информация32);
```

Параметры метода — допустимый вариант (запятая в начале строки):

```bsl
Функция ДокументФормаОткрыть(ДокументСсылка
	, ФормаВладелец = Неопределено
	, ОткрытиеПараметры = Неопределено) Экспорт

ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена()
	, ПолучитьНавигационнуюСсылку(Заказ)
	, Строка(Заказ)
	, БиблиотекаКартинок.Информация32);
```

> Запятая в начале строки сразу показывает, что строка продолжает список параметров. Строку с параметром легко закомментировать или удалить, не трогая соседние, а в сравнении версий меняется одна строка вместо двух.

Выравнивание по первому параметру не используется: оно ломается при переименовании метода и требует пробелов.

```bsl
// ❌ Плохо
ПоказатьОповещениеПользователя(пр_ЗаказТексты.ОтгрузкаЗавершена(),
                               ПолучитьНавигационнуюСсылку(Заказ));
```

Сложное условие:

```bsl
Если (Заказ.Статус = Перечисления.СтатусыЗаказовКлиентов.Согласован
	ИЛИ Заказ.Статус = Перечисления.СтатусыЗаказовКлиентов.КОтгрузке)
	И Заказ.ДатаОтгрузки <= ТекущаяДатаСеанса() Тогда

	пр_Отгрузка.Создать(Заказ);

КонецЕсли;
```

</details>

### 12.5 Коллекции и порядок

- **12.5.1** Структуру с более чем тремя ключами не создают через конструктор со списком ключей: такую строку сложно читать и дорабатывать. Ключи добавляются через `Вставить()`.
- **12.5.2** Там, где порядок не важен для логики (ключи структуры, перечни имён, строковые списки), элементы располагаются по алфавиту, а новый элемент сразу добавляется на своё место.

<details><summary>Пример к 12.5</summary>

```bsl
// ❌ Плохо: ключи и значения приходится сопоставлять по позиции
ДоговорДанные = Новый Структура("Наименование, Организация, ВидДоговора, ВалютаРасчетов, Контрагент",
	ДоговорНаименование, Организация, Перечисления.ВидыДоговоров.СПокупателем, ВалютаУчета, Контрагент);

// ✅ Хорошо: ключи по алфавиту, каждое значение рядом со своим ключом
ДоговорДанные = Новый Структура;
ДоговорДанные.Вставить("ВалютаРасчетов", ВалютаУчета);
ДоговорДанные.Вставить("ВидДоговора", Перечисления.ВидыДоговоров.СПокупателем);
ДоговорДанные.Вставить("Контрагент", Контрагент);
ДоговорДанные.Вставить("Наименование", ДоговорНаименование);
ДоговорДанные.Вставить("Организация", Организация);
```

</details>

## Пояснения и рекомендации

### Один оператор — одна строка

Несколько операторов на одной строке экономят место, но:

- прячут сложность: сложный код выглядит простым;
- заставляют читать строку целиком, а не скользить взглядом по левому краю;
- мешают отладке: отладчик выполняет строку целиком;
- усложняют правку и сравнение версий.

```bsl
// ❌ Плохо
Если Элементы.Описание.ТолькоПросмотр Тогда Элементы.Описание.ТолькоПросмотр = Ложь; Иначе Элементы.Описание.ТолькоПросмотр = Истина; КонецЕсли;

// ✅ Хорошо: разнесли по строкам — и стало видно, что ветвление не нужно
Элементы.Описание.ТолькоПросмотр = НЕ Элементы.Описание.ТолькоПросмотр;
```

Длинные цепочки вызовов — та же проблема: их сложно читать и невозможно отлаживать по шагам.

```bsl
// ❌ Плохо
Возврат Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Ссылка");
```

### Вертикальное разделение и сжатие

Код читается сверху вниз. Каждая группа строк — законченная мысль, а пустая строка — сигнал, что начинается следующая. Строки, тесно связанные по смыслу, наоборот, идут подряд без пустых строк. Взгляд при чтении цепляется за первые строки блоков, поэтому хорошо разделённый код можно «пролистать» глазами.

### Методы рядом с вызывающим

Методы, которые вызываются из метода верхнего уровня, располагаются сразу после него, в порядке вызова. Не разбрасывайте связанные методы по модулю: чем сильнее связь, тем ближе они должны стоять. Обработчик оповещения располагается сразу после метода, который его вызывает.

### Горизонтальное выравнивание

Выравнивание однотипных присваиваний допустимо и иногда подчёркивает их связь. Выравнивание делается табуляцией. Но не применяйте его механически: при переименовании выравнивание ломается, а иногда оно отвлекает больше, чем помогает. Цель — читаемость, а не соблюдение формы.
