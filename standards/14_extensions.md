# 14. Расширения

[↑ Оглавление](./README.md)

> Как дорабатывать типовую конфигурацию расширениями, не усложняя её обновление.

**Коротко**

- Расширений — как можно меньше, у каждого ясное назначение.
- Заимствуем только то, что действительно меняем.
- Дополняем, а не подменяем: `&Перед` и `&После` лучше `&Вместо`. `&Вместо` — только с `ПродолжитьВызов()`.
- Заимствованные формы пустые, все изменения формы — кодом.

## Правила

### 14.1 Состав расширений

- **14.1.1** Проектное расширение оформляется отдельной подсистемой в рамках БСП. Версии и обновление ведутся [стандартным механизмом БСП](https://its.1c.ru/db/v8std/content/690/hdoc) или [библиотекой обновления компонент](https://gitlab.com/bsl-libs/update_components_ext).
- **14.1.2** У расширения, меняющего типовой функционал, есть явный перечень изменений — в описании расширения или во внешней документации.
- **14.1.3** В идеале расширение одно. Если их несколько, у каждого чёткое назначение, и их изменения не пересекаются. Расширения с похожими или пустыми именами (`Расширение1`, `ОбщиеДоработки`) запрещены.
- **14.1.4** Если объект можно изменить расширением, его меняют расширением, а не снятием конфигурации с поддержки. Исключение — новые хранимые данные: объекты и реквизиты добавляются в конфигурацию ([13.1.4](./13_typical_changes.md#131-общие-правила)).

<details><summary>Пример к 14.1.3</summary>

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `Расширение1`, `Расширение2`, `ОбщиеДоработки`, `ИзмененияИнтерфейса` | `пр_ЗакупкиДоработки` — доработки подсистемы закупок; `пр_ИнтеграцияWMS` — обмен со складской системой |

</details>

### 14.2 Заимствование

- **14.2.1** Заимствуется только то, что расширение действительно меняет: модуль, форма, состав или свойства объекта. Ни больше, ни меньше. Обращаться к объектам конфигурации из кода расширения (`Справочники.Склады`, `Перечисления.…`) можно без заимствования.
- **14.2.2** В свойствах расширения выключена опция «Поддерживать соответствие объектам расширяемой конфигурации по внутренним идентификаторам».

### 14.3 Методы

- **14.3.1** Способ изменения выбирается в таком порядке:
  1. подписка на событие — чтобы изменить поведение при событиях объектов;
  2. `&Перед` и `&После` — чтобы дополнить метод;
  3. `&ИзменениеИКонтроль` — когда нужно изменить середину метода;
  4. `&Вместо` — только с вызовом `ПродолжитьВызов()`.
- **14.3.2** `&Вместо` без `ПродолжитьВызов()` запрещено.
- **14.3.3** Имя метода расширения начинается с префикса расширения.
- **14.3.4** У метода, который перехватывает типовой метод или обработчик, есть описание в одну-две строки: **что и зачем** меняется. Параметры не описываются — они совпадают с типовыми, а проверка их описания отключается комментарием `BSLLS:MissingParameterDescription-off`.

<details><summary>Примеры к 14.3</summary>

`&После` — дополнение типового метода:

```bsl
// Дополняет типовое заполнение: склад по умолчанию из настроек пользователя.
//
// BSLLS:MissingParameterDescription-off - см. синтакс-помощник
&После("ОбработкаЗаполнения")
Процедура пр_ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)

	пр_ЗаказКлиента.СкладПоУмолчаниюЗаполнить(ЭтотОбъект);

КонецПроцедуры
// BSLLS:MissingParameterDescription-on
```

`&Вместо` — только с продолжением вызова:

```bsl
// ❌ Плохо: логика типового метода «заморожена» — изменения вендора в ней не заработают
&Вместо("ЦенаРассчитать")
Функция пр_ЦенаРассчитать(Номенклатура, Дата)

	Результат = пр_Цена.ПоСоглашению(Номенклатура, Дата);

	Возврат Результат;

КонецФункции

// ✅ Хорошо: типовой расчёт выполняется, расширение корректирует результат

// Применяет к типовой цене скидку по соглашению с клиентом.
//
// BSLLS:MissingParameterDescription-off - см. типовой метод
&Вместо("ЦенаРассчитать")
Функция пр_ЦенаРассчитать(Номенклатура, Дата)

	Результат = ПродолжитьВызов(Номенклатура, Дата);
	Результат = пр_Цена.СкидкаПрименить(Результат, Номенклатура, Дата);

	Возврат Результат;

КонецФункции
// BSLLS:MissingParameterDescription-on
```

> Возвращаемое значение типовой функции через `&После` не изменить, поэтому здесь нужен `&Вместо` с `ПродолжитьВызов()`.

`&ИзменениеИКонтроль` — изменение в середине метода:

```bsl
// Добавляет к типовой проверке склада проверку его активности.
//
// BSLLS:MissingParameterDescription-off - см. типовой метод
&ИзменениеИКонтроль("СкладПроверить")
Процедура пр_СкладПроверить(Отказ)

	Если НЕ ЗначениеЗаполнено(Склад) Тогда
		Отказ = Истина;
	КонецЕсли;
	#Вставка
	// #4550 Склад должен быть активным
	Если НЕ Отказ И НЕ пр_Склад.Активен(Склад) Тогда
		Отказ = Истина;
	КонецЕсли;
	#КонецВставки

КонецПроцедуры
// BSLLS:MissingParameterDescription-on
```

</details>

### 14.4 Формы

- **14.4.1** Заимствованная форма остаётся пустой: в неё не заимствуются реквизиты и элементы, и новые не добавляются в редакторе формы.
- **14.4.2** Все изменения формы — реквизиты, элементы, команды, кнопки — делаются кодом в модуле формы расширения.
- **14.4.3** Первичное заимствование формы выполняется в пустой конфигурации «болванок» — см. статью [Модификация форм расширениями](../articles/modify_forms.md).

<details><summary>Пример к 14.4</summary>

```bsl
// Добавляет на форму элементы расширения.
// Обработчик назначен в свойствах заимствованной формы: событие «ПриСозданииНаСервере», вызов «После».
//
// BSLLS:MissingParameterDescription-off - см. синтакс-помощник
&НаСервере
Процедура пр_ПриСозданииНаСервереПосле(Отказ, СтандартнаяОбработка)

	пр_ЗаказКлиентаФорма.ЭлементыДобавить(ЭтотОбъект);

КонецПроцедуры
// BSLLS:MissingParameterDescription-on
```

```bsl
// Общий модуль пр_ЗаказКлиентаФорма

// Добавляет на форму заказа реквизит и поле «Приоритет отгрузки».
//
// Параметры:
//	Форма - ФормаКлиентскогоПриложения - форма документа «Заказ клиента».
//
Процедура ЭлементыДобавить(Форма) Экспорт

	РеквизитыНовые = Новый Массив;
	РеквизитыНовые.Добавить(Новый РеквизитФормы("пр_ПриоритетОтгрузки",
		Новый ОписаниеТипов("ПеречислениеСсылка.пр_ПриоритетыОтгрузки")));
	Форма.ИзменитьРеквизиты(РеквизитыНовые);

	Родитель = Форма.Элементы.Найти("ГруппаДоставка");
	Поле = Форма.Элементы.Добавить("пр_ПриоритетОтгрузки", Тип("ПолеФормы"), Родитель);
	Поле.Вид = ВидПоляФормы.ПолеВвода;
	Поле.ПутьКДанным = "пр_ПриоритетОтгрузки";

КонецПроцедуры
```

## Пояснения

### Зачем расширения

Главное преимущество расширений — основная конфигурация остаётся на поддержке. Обновление часто выполняет не самый опытный специалист, и наша задача — избавить его от проблем:

- доработок, потерянных при обновлении по невнимательности;
- мучительного сравнения и объединения модуля из-за мелкой правки;
- часов, а то и дней сравнения конфигурации поставщика с текущей.

Технология расширений активно развивается: с каждой версией платформы в расширении можно изменить всё больше.

### Заимствуем только нужное

Если свойства заимствованного объекта изменятся в основной конфигурации, расширение не подключится и покажет ошибку. Это полезно: проблема видна сразу, а не накапливается незаметно. Иногда ошибка возникает из-за изменений, которые на доработку не влияют, — это побочный эффект, и с ним можно жить. А если в расширении есть заимствованный объект, который не используется, — зачем он там?

### Сколько расширений

Чем больше расширений, тем выше шанс, что несколько из них меняют один объект. Найти все изменения становится трудно, а когда они найдены, оказывается, что есть ещё. Цель — чтобы место доработки находилось быстро и однозначно.

### Почему формы — только кодом

Если в заимствованной форме нет заимствованных реквизитов и элементов, её структура не «замораживается»: после обновления основной конфигурации форма перестраивается сама, а наши элементы добавляются кодом.

| Реквизиты формы не заимствованы | Элементы перестраиваются при обновлении |
|---|---|
| ![Реквизиты формы не заимствованы](./images/extension_form_props_import.png) | ![Перестроение элементов](./images/extension_form_props_refresh.png) |

Худшее, что может случиться, — из основной конфигурации исчезнет элемент-родитель или элемент, перед которым мы вставляем свой. Первый же дымовой тест это покажет, а исправление займёт минуты. Это несравнимо дешевле потерянных доработок после перестроения формы.

Кроме того, когда форму меняют несколько расширений, при объединении структур возникают «плавающие» ошибки платформы. Пустые заимствованные формы их исключают. Минус — разработка дольше, чем «накликать» элементы мышкой.

### `&Вместо` — бомба с таймером

`&Вместо` без `ПродолжитьВызов()` замораживает логику типового метода. Когда вендор изменит её в обновлении, никто не узнает: метод продолжит работать по-старому. Хорошо, если ошибку увидят сразу после обновления. Хуже, если о ней сообщит налоговая, получив отчётность, которая немного отличается от действительности.

С `ПродолжитьВызов()` аннотация безопасна. А `&Перед` и `&После` ещё лучше: по ним сразу видно, что типовой метод выполняется всегда и только дополняется — заглядывать внутрь не нужно.
