# <img src="./images/08_conf.png" align=top height=25 width=25/> 8. Объекты метаданных

## Правила

* **8.1** Для хранимых в базе данных объектов следуем [правилам именования классов объектов вендора](https://its.1c.ru/db/v8std#content:550:hdoc)
* **8.2** Объекты, ***не*** не хранимые в базе данных именуем согласно принципам ООП, описаным в [3. Имена](./code_standart_03_names.md#32-%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0-%D1%81%D0%BE%D1%81%D1%82%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D1%8F-%D0%B8%D0%BC%D0%B5%D0%BD%D0%B8-%D1%81%D1%82%D0%B8%D0%BB%D1%8C-%D0%BE%D0%BE%D0%BF)
* **8.3** Синоним объекта должен быть определен так, чтобы осмысленно и лаконично описывать объект. На проектах с мультиязычной поддержкой заполняется обязательно на всех языках, имеющихся в конфигурации.
* **8.4** Обычное и расширенное представление объекта/списка заполняется в случае, если формируемое представление на основании синонима не подходит (например, неверное согласование по числу или падежу).
* **8.5** При добавлении нового объекта надо обязательно добавить его в подсистему, настроить для него права доступа и при необходимости вывод в пользовательском интерфейсе.
* **8.6** Объекты (справочники, константы, и т.п.) должны быть отсортированы в дереве метаданных по имени. Подчиненные объекты метаданных, такие как реквизиты, измерения, формы, располагаются в дереве метаданных в соответствии с проектной логикой, а при ее отсутствии также должны быть отсортированы по имени.
* **8.7** Для хранения строк, максимально возможная длина которых заведомо известна, используются строковые реквизиты с длиной, равной максимально возможной. Когда максимально возможная длина строки неизвестна, для хранения используются строковые реквизиты неограниченной длины. При этом следует помнить о некоторых ограничениях возникающих при использовании полей неограниченной длины в языке запросов. В частности, при вычислении выражений в запросах такие реквизиты необходимо выражать как строку определенной длины, такой, чтобы выражение было вычислено верно.
* **8.8** Формы объектов конфигурации, имеющие смысл только в контексте других форм, не должны открываться посредством подменю "Операции" или другим способом, когда явно не задан владелец формы. В таких случаях обязательно должно выводиться поясняющее сообщение.
* **8.9** В качестве форм списка и выбора следует создавать разные формы, кроме случаев, когда это приводит к существенному дублированию кода, в таких случаях надо делать одну форму с правильной обработкой ее использования в качестве формы выбора.
* **8.10** Для типизированных объектов метаданных строкового типа надо использовать переменную длину строки. Свойство «Фиксированная длина» может устанавливаться только в тех случаях, когда действительно необходимо при манипуляции этими данными иметь гарантию, что строка имеет определенную длину, даже несмотря на наличие концевых пробелов.
* **8.11** Для любых элементов метаданных, у которых есть свойство «Проверка заполнения» (например это реквизиты объектов, измерения, ресурсы, реквизиты форм, не связанные с метаданными, и т. п.), следует выставлять это свойство в «Выдавать ошибку», если эти элементы должны быть заполнены хотя бы в одном из возможных вариантов выполнения кода. Также надо контролировать, чтобы свойство АвтоОтметкаНезаполненного соответствующего элемента формы было выставлено в Авто. Для вариантов, когда проверка не требуется, надо в событии ОбработкаПроверкиЗаполнения удалять эти элементы из массива проверяемых реквизитов.
* **8.12** Для удаления объектов, реквизитов или табличных частей необходимо захватывать все роли. Это вызвано необходимость корректного удаления ссылок на удаляемый объект метаданных.
* **8.13** Разработку ведем в режиме «управляемое приложение и обычное приложение». Всем клиентским модулям ставим также галочку «Клиент (обычное приложение)». Общий принцип: код должен работать при любой настройке свойств конфигурации, которая считается 1С нормальной (см. требования 1С: Совместимо). Аналогично галочкам используем директивы препроцессора и функции их заменяющие.
* **8.14**  В чистой (не объединенной с типовой) конфигурации/расширении используем «Использовать управляемые формы в толстом клиенте в обычном режиме».
* **8.15** Действия при старте системы должны отрабатывать в том числе и в толстом клиенте обычного приложения.
