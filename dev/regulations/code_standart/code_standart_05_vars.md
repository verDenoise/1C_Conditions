## Пояснения, рассуждения и рекомендации

### Одна цель

**Используйте каждую переменную только с одной целью**.

Иногда есть соблазн вызвать одну переменную в двух разных местах для решения двух разных задач. 

Обычно в таких случаях переменной приходится присваивать неудачное имя, соответствующее одной из ее целей, или использовать для решения обеих задач «временную» переменную (как правило, с бесполезным именем `н` или `врем`).

Иногда кажется, что переменная уже отработала своё, что в нее закладывали выше, и нет ничего лучше, чем использовать её имя повторно. Однако у такого подхода есть недостатки - программист, читающий такой текст, может не сразу, или вовсе не понять такие маневры.

### Скрытый смысл переменных

**Избегайте переменных, имеющих скрытый смысл**.

> ⚠️ Формально это называется «гибридным сопряжением»

Способ использования переменной более чем с одной целью заключается в том, что разные значения переменной имеют разный смысл. 

Значение переменной `КоличествоФайлов` представляет число файлов для загрузки, однако, если оно равно `-1`, автор кода подразумевает что произошла ошибка. Это неочевидность реализации, которая требует дополнительного описания в аннотации, либо дополнительного описания комментарием.

Однако, лучшей ситуацией будет вообще отсутствие скрытых смыслов переменных.

### Стандартные общепринятые переменные

Старайтесь использовать общепринятые имена. 

Например, используйте имя переменной "Отказ" вместо любых аналогий когда необходимо выполнить отмену действия после прохождения проверок.

### Утвердительные булевы переменные

**Используйте утвердительные имена булевых переменных**.

Значительно проще воспринимаются утвердительные имена, нежели отрицательные.

### Сокращение имен переменных

Стремление к сокращению имен переменных в некотором смысле стало пережитком.

Удачные короткие имена можно создать, устранив ненужные слова, выбрав более короткие синонимы и использовав какую нибудь из нескольких стратегий сокращения.

Помните, что имена создаются в первую очередь для программистов, читающих код Прочитайте собственный код, который вы не видели минимум шесть месяцев, и обратите внимание на те имена, суть которых вы не можете понять с первого взгляда. 

Измените подходы, подталкивающие к выбору таких имен.
