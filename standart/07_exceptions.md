# 7. Исключения и транзакции

[Оглавление](./README.md) | Назад: [6. Условия и циклы](./06_control_flow.md) | Далее: [8. Запросы](./08_queries.md)

## Правила

### 7.1 Попытка — Исключение

- **7.1.1** `Попытка` используется только там, где ошибка вероятна по причинам, не зависящим от качества кода: работа с файлами, внешними источниками данных и сервисами, разбор данных, корректность структуры которых не гарантирована.
- **7.1.2** `Попытка` не используется для проверки типа, наличия реквизита или метода у объекта, приведения значения к типу и как замена условному оператору.
- **7.1.3** Первым оператором блока `Исключение` получается информация об ошибке: `Информация = ИнформацияОбОшибке();`. Это упрощает отладку и гарантирует, что информация не будет потеряна последующим кодом. Исключение — блок с транзакцией: там первым вызывается `ОтменитьТранзакцию()` (правило 7.2.2).
- **7.1.4** Блок `Исключение` обязательно либо сообщает об ошибке пользователю, либо передаёт исключение выше через `ВызватьИсключение`. Пустой блок `Исключение` («проглатывание» ошибки) запрещён. Только запись в журнал регистрации без сообщения пользователю или повторного вызова исключения приравнивается к пустому блоку.
- **7.1.5** Исключения используются для передачи ошибки наверх с одновременным прекращением выполнения. Текст исключения содержит данные, по которым можно понять, где и почему возникла ошибка.
- **7.1.6** `ВызватьИсключение` без текста допускается в двух случаях:
  - внутри блока `Исключение` — для повторного вызова перехваченного исключения: исходная ошибка передаётся выше без изменений;
  - после того как сообщение уже выдано пользователю (например, с привязкой к полю формы).
- **7.1.7** Для представления ошибки используются методы объекта `ОбработкаОшибок`:
  - `ОбработкаОшибок.КраткоеПредставлениеОшибки(Информация)` — для пользователя;
  - `ОбработкаОшибок.ПодробноеПредставлениеОшибки(Информация)` — для журнала регистрации.

  Функцию `ОписаниеОшибки()` для этого не используем. Устаревшие варианты — в [Устаревших правилах](./99_deprecated.md).

Попытка вместо проверки:

```bsl
// ❌ Плохо: исключение как способ проверить наличие реквизита
Попытка
	Организация = Объект.Организация;
Исключение
	Организация = пр_Организация.Основная();
КонецПопытки;

// ✅ Хорошо
Если ОбщегоНазначения.ЕстьРеквизитОбъекта("Организация", Объект.Метаданные()) Тогда
	Организация = Объект.Организация;
Иначе
	Организация = пр_Организация.Основная();
КонецЕсли;
```

Попытка вместо приведения типа:

```bsl
// ❌ Плохо
Попытка
	ДнейКоличество = Число(ЗначениеСтрока);
Исключение
	ДнейКоличество = 0;
КонецПопытки;

// ✅ Хорошо: преобразование строки в число без исключений
ЧислоОписание = Новый ОписаниеТипов("Число");
ДнейКоличество = ЧислоОписание.ПривестиЗначение(ЗначениеСтрока);
```

«Проглатывание» исключения:

```bsl
// ❌ Плохо: ошибка пропадает бесследно
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
КонецПопытки;

// ❌ Тоже плохо: журнал регистрации оперативно никто не читает
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
	ЗаписьЖурналаРегистрации("Загрузка прайса", УровеньЖурналаРегистрации.Ошибка);
КонецПопытки;
```

Правильная обработка:

```bsl
// ✅ Хорошо: ошибка записана в журнал с подробностями и передана выше с понятным текстом
Попытка
	ФайлДанные = пр_Файл.Прочитать(ИмяФайла);
Исключение
	Информация = ИнформацияОбОшибке();
	ЗаписьЖурналаРегистрации(пр_ПрайсТексты.ЗагрузкаСобытие(), УровеньЖурналаРегистрации.Ошибка, , ,
		ОбработкаОшибок.ПодробноеПредставлениеОшибки(Информация));
	ВызватьИсключение СтрШаблон(пр_ПрайсТексты.ФайлЧтениеОшибка(), ИмяФайла,
		ОбработкаОшибок.КраткоеПредставлениеОшибки(Информация));
КонецПопытки;
```

### 7.2 Транзакции

- **7.2.1** Начало и завершение транзакции обязательно находятся в одном методе.
- **7.2.2** Явная транзакция оформляется так:
  - `НачатьТранзакцию()` стоит непосредственно перед `Попытка`;
  - последний оператор блока `Попытка` — `ЗафиксироватьТранзакцию()`;
  - в блоке `Исключение` **первым** вызывается `ОтменитьТранзакцию()`, затем ошибка записывается в журнал регистрации и передаётся выше через `ВызватьИсключение` ([стандарт 1С](https://its.1c.ru/db/v8std/content/783/hdoc)).
- **7.2.3** Транзакцию, которую начала платформа (например, при записи объекта), отменяем только установкой параметра `Отказ = Истина` в обработчике события.
- **7.2.4** Вложенные транзакции платформа поддерживает только на уровне кода, не на уровне базы данных. На каждый вариант выполнения каждому `НачатьТранзакцию()` соответствует ровно один `ЗафиксироватьТранзакцию()` или `ОтменитьТранзакцию()`. Одна отмена на любом уровне отменяет всю транзакцию целиком.
- **7.2.5** После ошибки обращения к базе внутри транзакции любое следующее обращение к базе вызывает ошибку «В данной транзакции уже происходили ошибки», пока не будет вызван `ОтменитьТранзакцию()`. Поэтому данные для сообщения об ошибке (реквизиты объекта и т. п.) читаются заранее или после отмены транзакции.

```bsl

//

			ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
```

## Пояснения и рекомендации

### Попытка — крайняя мера

**Если без `Попытка` можно обойтись, без неё нужно обходиться** ([стандарт 1С](https://its.1c.ru/db/v8std/content/499/hdoc)). Лишние попытки:

- усложняют отладку: ошибка перехватывается далеко от места возникновения;
- ухудшают читаемость: непонятно, какую ошибку ожидал автор;
- прячут настоящие ошибки среди «ожидаемых».

Механизм исключений нужен для одного: попытаться выполнить небезопасное действие так, чтобы можно было обработать ошибку.

### Почему журнал регистрации — не обработка

Журнал регистрации оперативно не читают, а иногда не читают вообще. Ошибка, записанная только в журнал, для пользователя не существует: он считает, что всё прошло успешно. Ключевые ошибки нужно показывать сразу или передавать выше, а журнал — дополнительный источник подробностей для разработчика.
