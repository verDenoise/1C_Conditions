# 8. Запросы

[Оглавление](./README.md) | Назад: [7. Исключения и транзакции](./07_exceptions.md) | Далее: [9. Формы и клиент-серверное взаимодействие](./09_forms.md)

## Правила

### 8.1 Оформление

- **8.1.1** Основной ориентир оформления — результат работы конструктора запроса.
- **8.1.2** Текст запроса начинается с новой строки. Отступы внутри текста — табуляцией, не пробелами.
- **8.1.3** Текст запроса передаётся сразу в конструктор `Новый Запрос(...)`. Отдельное присваивание `Запрос.Текст` допустимо, когда текст собирается динамически.
- **8.1.4** Запрос не пишется в одну строку, текст структурирован.
- **8.1.5** Псевдонимы полей и таблиц оставляем такими, какими их расставляет конструктор запроса, в том числе совпадающие с именем поля. Так текст запроса после правки в конструкторе не меняется лишний раз, и сравнение версий показывает только реальные изменения.
- **8.1.6** Длинным именам таблиц даются короткие осмысленные псевдонимы: `РаспределениеНастройки` вместо `БазаРаспределенияЗатратМеждународныйУчетСрезПоследних`.
- **8.1.7** Имена временных таблиц начинаются с `Таблица`: `ТаблицаОстатки`, `ТаблицаЗаказы`.
- **8.1.8** Текст запроса оформляется отдельной функцией. Так метод, который работает с результатом, становится короче, а запрос отделяется от обработки его результата.
- **8.1.9** Динамический или сложный запрос (больше пяти выборок, временных таблиц или соединений) начинается с комментария: что делает запрос и примерный план его выполнения.
- **8.1.10** При работе в конструкторе запроса сохраняйте комментарии, которые были в тексте: конструктор их удаляет.

<details><summary>Примеры к 8.1</summary>

```bsl
// ❌ Плохо: текст начинается на строке конструктора, пробелы вместо табуляции, нет псевдонимов
Запрос = Новый Запрос("ВЫБРАТЬ
|    Ссылка,
|    Код
|ИЗ
|    Справочник.Валюты");

// ✅ Хорошо
Запрос = Новый Запрос("
	|ВЫБРАТЬ
	|	Валюты.Ссылка КАК Ссылка,
	|	Валюты.Код КАК Код
	|ИЗ
	|	Справочник.Валюты КАК Валюты
	|");
```

Текст запроса в отдельной функции:

```bsl
// Остатки товаров на складе.
//
// Параметры:
//	Склад - СправочникСсылка.Склады - склад.
//
// Возвращаемое значение:
//	ТаблицаЗначений - колонки: Номенклатура, Количество.
//
Функция Остатки(Склад) Экспорт

	Запрос = Новый Запрос(ОстаткиЗапросТекст());
	Запрос.УстановитьПараметр("Склад", Склад);

	Результат = Запрос.Выполнить().Выгрузить();

	Возврат Результат;

КонецФункции

// Текст запроса остатков товаров на складе.
Функция ОстаткиЗапросТекст()

	Результат = "
	|ВЫБРАТЬ
	|	Остатки.Номенклатура КАК Номенклатура,
	|	Остатки.КоличествоОстаток КАК Количество
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки
	|";

	Возврат Результат;

КонецФункции
```

Комментарий к сложному запросу:

```bsl
	Результат = "
	|// Сверка документов поступления с данными поставщика.
	|//
	|// Шаги (каждый следующий работает с тем, что не попало в предыдущие):
	|//	1. ТаблицаЧерновики - документы есть, но не проведены
	|//	2. ТаблицаСовпадения - состав совпадает по номенклатуре и количеству
	|//	3. ТаблицаРасхождения - документ найден, состав отличается
	|//	4. ТаблицаЛишниеУНас - документы, которых нет у поставщика
	|//	5. ТаблицаЛишниеУПоставщика - данные поставщика без документа
	|//
	|// Псевдонимы: Поступления - наши документы, Поставщик - загруженные данные
	|
	|ВЫБРАТЬ
	|	// ...
	|";
```

### 8.2 Содержание

- **8.2.1** Константные значения (пустые даты и ссылки, предопределённые элементы, значения перечислений) пишутся прямо в тексте запроса: `ЗНАЧЕНИЕ(...)`, `ДАТАВРЕМЯ(1, 1, 1)`. Параметры для них не используются.
- **8.2.2** К реквизитам поля составного типа обращаемся через `ВЫРАЗИТЬ` с явным указанием типа. Иначе платформа неявно соединяет все таблицы, на которые может ссылаться поле.
- **8.2.3** Для объединения результатов используется `ОБЪЕДИНИТЬ ВСЕ`. `ОБЪЕДИНИТЬ` — только когда удаление одинаковых строк действительно нужно по логике.
- **8.2.4** Соединения с подзапросами, в том числе с виртуальными таблицами, запрещены ([стандарт 1С](https://its.1c.ru/db/metod8dev/content/5842/hdoc)). Подзапрос сначала помещается во временную таблицу. Исключение — места, где временные таблицы недоступны (RLS, динамические списки); такие запросы обязательно проходят внимательное ревью.
- **8.2.5** Виртуальные таблицы параметризуются условиями в параметрах таблицы, а не в секции `ГДЕ`.
- **8.2.6** `ДЛЯ ИЗМЕНЕНИЯ` применяется только к таблицам с автоматическим режимом блокировок. В управляемом режиме конструкция не работает — используйте `БлокировкаДанных`.
- **8.2.7** Перед выборкой из результата проверяется, что он не пустой: `Результат.Пустой()`.

<details><summary>Примеры к 8.2</summary>

Константы в тексте запроса:

```bsl
// ❌ Плохо: константы передаются параметрами
|ГДЕ
|	Заказы.Статус = &СтатусСогласован
|	И Заказы.ДатаОтгрузки <> &ПустаяДата

// ✅ Хорошо
|ГДЕ
|	Заказы.Статус = ЗНАЧЕНИЕ(Перечисление.СтатусыЗаказовКлиентов.Согласован)
|	И Заказы.ДатаОтгрузки <> ДАТАВРЕМЯ(1, 1, 1)
```

Поле составного типа:

```bsl
// ❌ Плохо: неявные соединения со всеми таблицами типов поля Регистратор
|ВЫБРАТЬ
|	Движения.Регистратор.Контрагент КАК Контрагент

// ✅ Хорошо
|ВЫБРАТЬ
|	ВЫРАЗИТЬ(Движения.Регистратор КАК Документ.РеализацияТоваровУслуг).Контрагент КАК Контрагент
```

Соединение с виртуальной таблицей:

```bsl
// ❌ Плохо: соединение с виртуальной таблицей (подзапросом на уровне СУБД)
|ВЫБРАТЬ
|	Товары.Номенклатура КАК Номенклатура,

|		ПО Товары.Номенклатура = Остатки.Номенклатура

// ✅ Хорошо: товары и остатки — во временные таблицы, отбор остатков — в параметрах виртуальной таблицы
|ВЫБРАТЬ
|	Товары.Номенклатура КАК Номенклатура
|ПОМЕСТИТЬ ТаблицаТовары

|	Товары.Ссылка = &Заказ

|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(,
|		Номенклатура В
|			(ВЫБРАТЬ
|				ТаблицаТовары.Номенклатура
|			ИЗ
|				ТаблицаТовары КАК ТаблицаТовары)) КАК Остатки

|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура
```

## Чек-лист проверки запроса

Всё основное о запросах — в [требованиях 1С](https://its.1c.ru/db/metod8dev/content/5842/hdoc). Ниже — вопросы, которые стоит задать себе при проектировании запроса.

**Параметры**

- [ ] Параметры вычислены до выполнения запроса, а не внутри текста?

**Виртуальные таблицы**

- [ ] Отборы перенесены в параметры виртуальной таблицы, насколько это возможно?
- [ ] Для `СрезПоследних` не передаётся период, если нужны текущие данные? Тогда используются текущие итоги (если они включены у регистра).
- [ ] Если период оборотов не кратен месяцу или периодичность меньше месяца, таблица итогов не используется. Возможно, эффективнее выбрать из физической таблицы движений.
- [ ] Если у регистра остатков нужны только обороты — таблица оборотов у него не хранится, возможно, лучше выбрать из физической таблицы.
- [ ] Обороты выбираются без начальной даты? Без других отборов выборка растёт вместе с таблицей итогов, а после свёртки базы результат может измениться.

**Оператор `ПОДОБНО`**

- [ ] Шаблон начинается с `%`? Тогда индекс не используется. То же относится к отбору «Содержит» в динамическом списке. Применяйте такие шаблоны осознанно.

**Соединения**

- [ ] Соединений немного? Платформа добавляет свои неявные соединения (составные типы, RLS, представления), поэтому реальное их число больше видимого. Практический ориентир — если явных соединений больше 7–8, подумайте, как упростить запрос.
- [ ] Можно ли заменить соединение объединением? Объединение для СУБД дешевле.
- [ ] Нет полных соединений? Их, как правило, можно заменить объединением.
- [ ] Нет соединений с виртуальными таблицами и подзапросами (правило 8.2.4)? Если есть сомнение, что временная таблица выгоднее, — посмотрите план запроса или обратитесь к ведущему разработчику.
- [ ] Нет подзапросов в условии соединения или в `ГДЕ`, которые можно заменить соединением с временной таблицей?

**Индексы**

- [ ] Условия используют поля индекса без пропусков в порядке их следования? Иногда стоит добавить условие на пропущенное поле или перестроить индекс, но тогда проверьте, не пострадают ли другие запросы к таблице.
- [ ] Временные таблицы проиндексированы по полям соединений **там, где индекс будет использован**? При соединении hash match или когда временная таблица стоит слева в nested loop индекс не используется, и ресурсы на индексацию тратятся впустую.

**Временные таблицы**

- [ ] Нет лишних временных таблиц? Каждая нагружает `tempdb` СУБД.

**Составной тип**

- [ ] Нет обращения через точку к полям составного типа без `ВЫРАЗИТЬ`?
- [ ] `ВЫРАЗИТЬ(...)` в `ГДЕ` и `ПО` без последующего обращения к реквизиту через точку может привести к сканированию таблицы.
- [ ] Для обращения к реквизитам поля составного типа используется `ВЫРАЗИТЬ(... КАК ...)` (правило 8.2.2), а для проверки типа — `ССЫЛКА` или `ТИПЗНАЧЕНИЯ()`, а не обращение через точку.

**Условие `ИЛИ`**

- [ ] `ИЛИ` по одному полю — индекс используется, проблем нет.
- [ ] `ИЛИ` по разным индексированным полям — индекс может использоваться, а может нет: зависит от размера таблицы, селективности и статистики. Проверяйте план запроса. Часто лучше заменить на `ОБЪЕДИНИТЬ ВСЕ`.
- [ ] `ИЛИ` по разным полям, где хотя бы одно без индекса, — гарантированное сканирование таблицы.

```bsl
// ❌ Возможно сканирование таблицы
|ГДЕ
|	Реализация.Номер = &Номер
|	ИЛИ Реализация.Контрагент = &Контрагент

// ✅ Каждая часть использует свой индекс
|ВЫБРАТЬ
|	Реализация.Ссылка КАК Ссылка
|ИЗ
|	Документ.РеализацияТоваровУслуг КАК Реализация
|ГДЕ
|	Реализация.Номер = &Номер
|
|ОБЪЕДИНИТЬ ВСЕ
|
|ВЫБРАТЬ
|	Реализация.Ссылка КАК Ссылка
|ИЗ
|	Документ.РеализацияТоваровУслуг КАК Реализация
|ГДЕ
|	Реализация.Контрагент = &Контрагент
```

> Для запроса с `ОБЪЕДИНИТЬ ВСЕ` один и тот же документ может попасть в результат дважды. Если это важно, используйте `ОБЪЕДИНИТЬ` (правило 8.2.3 это разрешает, когда удаление дублей нужно по логике).
