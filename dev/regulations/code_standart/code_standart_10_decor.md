## Правила

* **10.1** Форматирование должно соответствовать форматированию платформы 1С (которое производится по нажатию кнопки "Форматировать"), проще всего этого добиться следующими действиями: выделить все и нажать кнопку "Форматировать". Это же касается текста запросов (см. раздел «Запросы»).
* **10.2** Для организации отступов в начале строк допускается использование только символов табуляции, пробелы использовать не допускается.
* **10.3** Описания процедур и функций должны отделяться друг от друга (и от других разделов модуля) в тексте модуля пустыми строками. В том числе в конце модуля должен быть перевод строки. В других местах пустые строки использовать не следует.
* **10.4** Тексты модулей оформляются по принципу "один оператор в одной строке". Переносы длинных строк допускаются (например, конкатенация строк, запросы, длинные условия), обратная ситуация (больше одной «;» в строке) – не допускается.
* **10.5** Длина строки не должна превышать 120 символов, жедательная длина не более 80 символов.
* **10.6** В выражениях необходимо отделять операнды от знаков операций пробелами (по одному с каждой стороны). После открывающей скобки пробел не ставится. После запятой пробел ставится (в том числе и для параметров процедур/функций), перед запятой – не ставится.
* **10.7** Сложные логические условия в Если…ИначеЕсли…КонецЕсли могут переноситься следующим образом:
  - каждое элементарное условие может начинать новую строку,
  - логические операторы ставятся в начале строки, а не в конце предыдущей строки
  - условия выравниваются по началу Если + одна табуляция, с учетом логического оператора
  - ключевое слово `Тогда` пишется на той же строке, что и последнее условие.
  - группы условий необходимо выделять скобками, не надеясь на порядок выполнения
* **10.8** При переносе следуем правилу каждая новая строка должна начинаться со спецсимвола кроме переносов параметров методов ([стандарт вендора](https://its.1c.ru/db/v8std/content/444/hdoc)). Правила переноса:
  - Длинные арифметические выражения: 
    - В одной строке может находиться более одного операнда
    - Знаки операции пишутся в начале строки (а не в конце предыдущей строки)
    - Операции выравниваются по первому символу оператора.
    > *Пример:*
    >
    > ```bsl
    > ДокументСумма = СуммаСкидкаОтсутствует
    > + СуммаСкидкаРучная
    > + СуммаСкидкаАвтоматическая;
    > ```
  - Многострочный текст: новые строки выравниваются по первому символу оператора
    > *Пример:*
    > 
    > ```bsl
    > ЗапросТекст = "
    > |ВЫБРАТЬ
    > |    *
    > ```
  - Параметры объявлений методов: новые строки выравниваются по началу объявления + одна табуляция
    > *Пример:*
    > 
    > ```bsl
    > Функция ФормаОткрыть(Имя,
    >     Оповещение = Неопределено,
    >     Параметры = Неопределено,
    >     Владелец = Неопределено,
    >     Уникальность = Неопределено,
    >     Окно = Неопределено,
    >     НавигационнаяСсылка = Неопределено,
    >     РежимОткрытия = Неопределено) Экспорт
    > ```
  - Параметры вызовов методов: новые строки выравниваются по первомы символу оператора + одна табуляция.
    > *Пример:*
    > 
    > ```bsl
    > ПредупреждениеПоказать(Оповещение,
    >     "Выполнение операции завершено.",
    >     , 
    >     "Заполнение таблицы");
    > ```

## Пояснения, рассуждения и рекомендации

### Перенос длинных выражений

> ⚠️ Длина строки кода не должна превышать 120-130 символов. Она становится не читаемая, заставляет читающего двигать полосу прокрутки вправо, отнимая время на чтение кода. Строки длиннее 120-130 символов препятствуют созданию глубокой вложенности.

**Очевидность наличия переноса**.

Сделайте так, чтобы незавершенность выражения первой строки была очевидна. Как правило очевидность переноса достигается открытой скобкой метода:

```bsl
НоваяНоменклатура = СоздатьНовуюПозициюНоменклатуры(ДополнительныеПараметры.НаименованиеВФайле,
    ДополнительныеПараметры.КодВФайле, ДополнительныеПараметры.СтавкаНДС);

НоваяНоменклатура = СоздатьНовуюПозициюНоменклатуры(
    ДополнительныеПараметры.НаименованиеВФайле,
    ДополнительныеПараметры.КодВФайле, 
    ДополнительныеПараметры.СтавкаНДС);
```

**Размещение знака продолжения в начале перенесенной строки а не в конце переносимой**.

*Корректный и очевидный перенос*:

```bsl
ИмяФайла = "Остатки" + ВыборкаДетальныеЗаписи.ДатаДокумента + " по складу "
    + ВыборкаДетальныеЗаписи.СкладПредставление + "." + ВыбранноеПользователемРасширение;
```

*Не очевидный (стандарты ИТС его вовсе запрещают)*:

```bsl
ИмяФайла = "Остатки" + ВыборкаДетальныеЗаписи.ДатаДокумента + " по складу " +
    ВыборкаДетальныеЗаписи.СкладПредставление + "." + ВыбранноеПользователемРасширение;
```

**Стандартный отступ**.

Одна из наиболее неприятных проблем форматирования — решение о том, что делать с частью выражения, переносимой на следующую строку. Делать ли нормальный отступ? Или выровнять его по ключевому слову? А что делать с присваиваниями?

При переносе строк в вызове метода используйте отступ стандартного размера (не 1 пробел, не три пробела, ни пять. Только один символ табуляции, либо выравнивание по первому аргументу).

*Первый стиль*:

```bsl
ПоказатьОповещениеПользователя("Оформление документов завершено!",
    "e1cib/list/Документ.ОтчетОРозничныхПродажах",
    "Открыть Отчеты о розничных продажах",
    БиблиотекаКартинок.Информация32);
```

*Второй стиль*:

```bsl
ПоказатьОповещениеПользователя("Оформление документов завершено!",
                               "e1cib/list/Документ.ОтчетОРозничныхПродажах",
                               "Открыть Отчеты о розничных продажах",
                               БиблиотекаКартинок.Информация32);
```

С эстетической точки зрения, в сравнении с первым вариантом этот код выглядит несколько неровно. Кроме того, этот подход тяжело сопровождать, так как имена методов и аргументов могут изменяться. Большинство программистов со временем склоняются к использованию первого стиля.

### Вертикальное разделение концепций переносами строки

**Вертикальное разделение**.

Следует отделять друг от друга переносом сток ключевые логические структуры.

Практически весь код читается слева направо и сверху вниз. Каждая строка представляет выражение или условие, а каждая группа строк представляет законченную мысль. Эти мысли следует отделять друг от друга пустыми строками.

Каждая пустая строка – зрительная подсказка: описание одной концепции закончилось, далее следует новая. При просмотре кода взгляд концентрируется на первых строчках – в них больше всего информации, как в началах абзацев этого текста.

```bsl
...

ИначеЕсли РезультатОбработкиШтрихкода.ПараметрыВыбораНоменклатуры.ТипШтрихКода = Перечисления.ТипыШтрихкодов.DataMatrix Тогда
                    // <-- Строка-разделитель логических блоков кода
    РезультатДобавлениеШтрихкодаВДокумент = МенеджерДокумента.ОбработатьШтрихкодDataMatrix(
        Форма,
        ДанныеШтрихкода,
        ПараметрыСканирования);
                    // <-- Строка-разделитель логических блоков кода
Иначе
                    // <-- Строка-разделитель логических блоков кода
    ВложенныеШтрихкода = ПолучитьИзВременногоХранилища(РезультатОбработкиШтрихкода.АдресДереваУпаковок);
                    // <-- Строка-разделитель логических блоков кода
    РезультатДобавленияШтрихкодаВДокумент = МенеджерДокумента.ОбработатьШтрихкодУпаковки(
        Форма,
        ДанныеШтрихкода,
        ВложенныеШтрихкоды,
        ПараметрыСканирования);
                    // <-- Строка-разделитель логических блоков кода
    ОбработатьРезультатДобавленияШтрихкодаУпаковки(
        Форма,
        ДанныеШтрихкода,
        ПараметрыСканирования,
        РезультатДобавленияШтрихкодаВДокумент);
                    // <-- Строка-разделитель логических блоков кода
КонецЕсли;
                    // <-- Строка-разделитель логических блоков кода
Возврат РезультатДобавленияШтрихкодаВДокумент;
```

**Вертикальное сжатие**.

Если вертикальные пропуски разделяют концепции, то вертикальное сжатие подчеркивает тесные связи. Таким образом, строки кода, между которыми существует тесная связь, должны быть «сжаты» по вертикали

**Концептуальное родство методов**.

Некоторые методы кода требуют, чтобы их разместили вблизи от других методов. Такие фрагменты обладают определенным концептуальным родством. **Чем сильнее родство, тем меньше должно быть вертикальное расстояние между ними**. Например методы, вызываемые из метода верхнего уровня абстракции должны идти сразу на ним. Не стоит их разбрасывать по всему модулю.

**Конструкторы структур**.

При наличии у структуры более 3х ключей - не стоит использовать конструктор. Это **сложно читается**, и еще **более сложно дорабатывается**. *Например*:

### Сильно связанные элементы вместе

> ⚠️ Не заставляйте читателя прыгать туда-сюда по методу в поисках где же была объявлена та или иная переменная.

Концепции, тесно связанные друг с другом, должны находиться поблизости друг от друга по вертикали. Их вертикальное разделение должно показывать, насколько они важны для понимания друг друга. Объявление локальной переменной не должно отдаляться от места ее использования на сотню строк, они должны объявляться рядом с местом их первого использования.

Исключения из этого правила является объявление в начале метода переменной, возвращающей результат выполнения функции.

Пример сильно сокращен (что бы не тратить время читателя на скроллинг). Реальный метод в несколько раз больше, найти объявление переменной "СтруктураПисьма" оказалось не так быстро.

```bsl
// !!! ВНИМАНИЕ, здесь объяаление переменной
СтруктураПисьма = Новый Структура("ИнтернетПочтовоеСообщение, ДатаПисьма");

Запрос = Новый Запрос;
Запрос.Текст = ""; // <-- Автор пропустил длинный текст запроса, который еще более усложныл метод

Запрос.УстановитьПараметр("Письмо", Письмо);

РезультатЗапроса = Запрос.ВыполнитьПакет();

ВыборкаШапка = РезультатЗапроса[0].Выбрать();
Если ВыборкаШапка.Следующий() Тогда

    ОбъектИнтернетПочтовоеСообщение = Новый ИнтернетПочтовоеСообщение;
    ОбъектИнтернетПочтовоеСообщение.Важность = УправлениеЭлектроннойПочтой.ПолучитьВажность(ВыборкаШапка.Важность);
    ОбъектИнтернетПочтовоеСообщение.Идентификатор.Добавить(ВыборкаШапка.Идентификатор);
    ОбъектИнтернетПочтовоеСообщение.Кодировка = ВыборкаШапка.Кодировка;
    ОбъектИнтернетПочтовоеСообщение.Тема = ВыборкаШапка.Тема;
    ОбъектИнтернетПочтовоеСообщение.УведомитьОДоставке = ВыборкаШапка.УведомитьОДоставке;
    ОбъектИнтернетПочтовоеСообщение.УведомитьОПрочтении = ВыборкаШапка.УведомитьОПрочтении;

    ДанныеОтправителя = ОбщегоНазначенияКлиентСервер.РазобратьСтрокуСПочтовымиАдресами(ВыборкаШапка.ОтправительПредставление, Ложь);

    Если ТипЗнч(ДанныеОтправителя) = Тип("Массив") И ДанныеОтправителя.Количество() > 0 Тогда
        ОбъектИнтернетПочтовоеСообщение.ИмяОтправителя = ДанныеОтправителя[0].Представление;
        ОбъектИнтернетПочтовоеСообщение.Отправитель = ДанныеОтправителя[0].Адрес;
    КонецЕсли;

    Если ПустаяСтрока(ВыборкаШапка.ТекстHTML) Тогда

        ДобавитьТекстВТекстыИнтернетПочтовогоСообщения(ОбъектИнтернетПочтовоеСообщение.Тексты,
                                                       ВыборкаШапка.Текст,
                                                       ТипТекстаПочтовогоСообщения.Текст,
                                                       ВыборкаШапка.Кодировка);

    КонецЕсли;

Иначе

    Возврат Неопределено;

КонецЕсли;

ДобавитьПолучателяВПочтовоеСообщениеПоВыборке(ОбъектИнтернетПочтовоеСообщение, РезультатЗапроса[1].Выбрать(), "Получатели");
ДобавитьПолучателяВПочтовоеСообщениеПоВыборке(ОбъектИнтернетПочтовоеСообщение, РезультатЗапроса[2].Выбрать(), "ОбратныйАдрес");
ДобавитьПолучателяВПочтовоеСообщениеПоВыборке(ОбъектИнтернетПочтовоеСообщение, РезультатЗапроса[3].Выбрать(), "Копии");

// !!! ВНИМАНИЕ, а только здесь первое использование значитено выше объявленной переменной
СтруктураПисьма.ИнтернетПочновоеСообщение = ОбъектИнтернетПочтовоеСообщение;
СтруктураПисьма.ДатаПисьма = ВыборкаШапка.ДатаОтправления;
```

### Горизонтальное форматирование

**Используйте пробелы, чтобы сделать читаемыми логические выражения.**

Пробелы улучшают читаемость кода, если они стоят вокруг операторов присваивания, после запятых при перечислении переменных. В формулах пробелы используются для подчеркивания приоритета: не ставятся между множителями, но отбивают знаки сложения и вычитания.

```bsl
// Трудно прочитать
Значение="ИБ"+СокрЛП(Номер)+" "+Формат(Дата,"ДФ=дд.ММ.гггг");

// Легче прочитать
Значение = "ИБ" + СокрЛП(Номер) + " " + Формат(Дата,"ДФ=дд.ММ.гггг");
```

**Используйте пробелы, чтобы сделать читаемыми аргументы методов**.

Назовите четвертый аргумент следующего метода: `ReadEmployeeData(maxEmps,empData,inputFile,empCount,inputError)`

А теперь назовите четвертый аргумент этого метода:

`GetCensus(inputFile, empCount, empData, maxEmps, inputError)`

Какой из них было легче найти?

**Горизонтальное разделение и сжатие**.

**Знаки присваивания окружены пробелами**, обеспечивающими их визуальное выделение. Операторы присваивания состоят из двух основных элементов: левой и правой частей. Пробелы наглядно подчеркивают это разделение.

**Горизонтальное выравнивание**.

Возможно выравнивание однотипных операторов. Это подчеркивает их связанность друг с другом, а так же отношение к одному уровню абстракции.

> 👉 Выравнивание следует выполнять с помощью символов табуляции.

```bsl
// Трудно прочитать
НоваяСтрока = ТаблицаШтрихкодов.Добавить();
НоваяСтрока.ШтрихкодУпаковки = СтрокаТЧ.АкцизнаяМарка;
НоваяСтрока.ШтрихкодРодительскойУпаковки = СтрокаТЧ.ШтрихкодУпаковки;
НоваяСтрока.ИдентификаторСтроки = СтрокаТЧ.ИдентификаторСтроки;
НоваяСтрока.Справка2 = СтрокаТЧ.Справка2;
НоваяСтрока.ОрганизацияЕГАИС = ОрганизацияЕГАИС;

// Легче прочитать
НоваяСтрока = ТаблицаШтрихкодов.Добавить();
НоваяСтрока.ШтрихкодУпаковки                = СтрокаТЧ.АкцизнаяМарка;
НоваяСтрока.ШтрихкодРодительскойУпаковки    = СтрокаТЧ.ШтрихкодУпаковки;
НоваяСтрока.ИдентификаторСтроки             = СтрокаТЧ.ИдентификаторСтроки;
НоваяСтрока.Справка2                        = СтрокаТЧ.Справка2;
НоваяСтрока.ОрганизацияЕГАИС                = ОрганизацияЕГАИС;
```

Однако не стоит слепо следовать этой рекомендации, т.к. не во всех ситуациях такое выравнивание уместно. Иногда выравнивание ухудшает читаемость кода и заставляет фокусировать внимание на таком виде форматирования. 
Наша цель - не соблюдение того или иного стандарта, а максимальная читаемость кода.

В каждой ситуации принимайте решение - использовать горизонтальное выравнивание или нет.

### Один оператор на одной строке

> ⚠️ Одна строка кода - одна управляющая конструкция.

Аргументом в защиту размещения нескольких выражений на одной строке может служить факт, что в этом случае требуется меньшее число строк экранного пространства, что позволяет одновременно видеть больший объем кода. Это также позволяет сгруппировать взаимосвязанные выражения. Все так, но основания для самоограничения, требующие оставлять не более одного оператора в строке, гораздо серьезней:

- Размещение каждого оператора на отдельной строке дает точное представление о сложности программы. При этом не скрывается сложность из-за того, что сложные операторы выглядят тривиальными. Сложные операторы и выглядят сложными, простые - простыми.
- Если операторы расположены на отдельных строках, чтение кода происходит сверху вниз, а не сверху вниз и слева направо. При поиске определенной строки у взгляда должна быть возможность придерживаться левого края кода. Он не должен просматривать каждую строку целиком только потому, что в одной строке может быть два оператора.
- При размещении операторов на отдельных строках легко выполнять пошаговую отладку кода, используя построчные отладчики. Если строка содержит несколько операторов, отладчик выполнит их все одновременно.
- Когда строка содержит только один оператор, его легко редактировать — можно удалить или временно закомментировать всю строку. Если же на одной строке вы разместили несколько операторов, вам придется выполнять редактирование между остальными операторами.

*Пример* неудачного кода:

```bsl
&НаКлиенте
Процедура ТолькоПросмотр(Команда)
    Если Элементы.Описание.ТолькоПросмотр = Истина Тогда Элементы.Описание.ТолькоПросмотр = Ложь;
    Иначе Элементы.Описание.ТолькоПросмотр = Истина;
    КонецЕсли;
КонецПроцедуры
```

После размещения каждого оператора на отдельной строке стал более ясен код, а вслед за этим и механизм его преобразования стал очевиден.

```bsl
&НаКлиенте
Процедура ТолькоПросмотр(Команда)

    Элементы.Описание.ТолькоПросмотр = НЕ Элементы.Описание.ТолькоПросмотр;

КонецПроцедуры
```

Еще *пример*:

```bsl
Возврат Запрос.Выполнить().Выгрузить().Свернуть("Ссылка").ВыгрузитьКолонку("Ссылка");
```

> 👉 Такие конструкции не только сложно читаются, но и непросто отлаживаются.

### Регистр букв

> ⚠️ Все конструкции должны быть написаны с больший буквы. Ошибкой является написание "капсом", с маленькой буквы и прочие отклонения.

[Требования ИТС](https://its.1c.ru/db/v8std#content:441:hdoc)

```bsl
// Трудно прочитать
если КлючДанных или Отказ тогда
    ТипЗначенияСтрокой = неопределено;
ИНАЧЕ
    ТипЗначенияСтрокой = XMLТипЗнч(КлючДанных).ИмяТипа;
конецесли;

// Легче прочитать
Если КлючДанных Или Отказ Тогда
    ТипЗначенияСтрокой = Неопределено;
Иначе
    ТипЗначенияСтрокой = XMLТипЗнч(КлючДанных).ИмяТипа;
КонечЕсли;
```
