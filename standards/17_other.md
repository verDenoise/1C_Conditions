# 17. Прочее

[↑ Оглавление](./README.md)

> Полезные практики, которые не вошли в другие главы.

## Правила

- **17.1** Первичные данные, нужные для проведения и печати документа, хранятся в самом документе, а не читаются из базы в момент проведения. Тогда результат проведения не зависит от того, что изменилось в справочниках после ввода документа.
- **17.2** Для каждого регламентного задания, запускаемого через консоль, заводится отдельный служебный пользователь. Его имя отражает назначение задания.
- **17.3** Внешние подключения к базе (COM, веб-сервисы, HTTP-сервисы) выполняются под отдельными служебными пользователями. По имени пользователя понятно, откуда и зачем подключение.

<details><summary>Примеры</summary>

Данные для проведения (17.1):

```bsl
// ❌ Плохо: ставка НДС читается из справочника в момент проведения —
// при перепроведении старого документа сумма налога изменится
СтавкаНДС = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(ТоварыСтрока.Номенклатура, "СтавкаНДС");

// ✅ Хорошо: ставка сохранена в строке документа при вводе
СтавкаНДС = ТоварыСтрока.СтавкаНДС;
```

Служебные пользователи (17.2, 17.3):

| Назначение | ❌ Плохо | ✅ Хорошо |
|---|---|---|
| Регламентное задание загрузки курсов валют | `Админ`, `Робот` | `РегламентЗагрузкаКурсовВалют` |
| HTTP-сервис для сайта | `web`, `Сервис` | `HTTPСайтЗаказы` |
| Обмен с WMS через COM | `Обмен` | `COMОбменWMSОстатки` |

> Это имена пользователей информационной базы, а не элементов кода, поэтому правила главы 2 к ним не применяются. Главное — по имени понятно, кто и зачем подключается.

</details>
