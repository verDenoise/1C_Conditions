# 10. Объекты метаданных

[↑ Оглавление](./README.md)

> Как называть объекты конфигурации и настраивать их свойства.

**Коротко**

- Объекты метаданных называются по правилам 1С, с префиксом подсистемы. Общие модули — в объектном стиле.
- Новый объект сразу попадает в подсистему и получает права.
- Порядок значений перечислений и измерений регистров не трогаем.
- Проверка заполнения — средствами платформы, а не кодом.

## Правила

### 10.1 Имена и представления

- **10.1.1** Все объекты метаданных, кроме общих модулей, называются по [правилам 1С](https://its.1c.ru/db/v8std/content/550/hdoc), естественным русским языком, с префиксом подсистемы ([2.1.8](./02_names.md#21-общие-правила)). Это касается и хранимых объектов (справочники, документы, регистры, константы, перечисления), и нехранимых (отчёты, обработки, подписки на события, регламентные задания, роли, функциональные опции).
- **10.1.2** Общие модули называются в объектном стиле ([2.2.2–2.2.5](./02_names.md#22-объектный-стиль)) с суффиксами по правилу 2.2.5.
- **10.1.3** Синоним кратко и точно описывает объект. В мультиязычной конфигурации синоним заполняется на всех её языках.
- **10.1.4** Представление объекта и списка (обычное и расширенное) заполняется, если представление по синониму не подходит — например, неверно согласуются число или падеж.

<details><summary>Примеры к 10.1</summary>

| Вид объекта | ❌ Плохо | ✅ Хорошо |
|---|---|---|
| Справочник | `Склад`, `пр_СправочникСкладов` | `пр_Склады` |
| Документ | `пр_ДокументЗаявки` | `пр_ЗаявкаНаЗакупку` |
| Регистр сведений | `пр_Цены` (непонятно чего) | `пр_ЦеныПоставщиков` |
| Обработка | `пр_ОбработкаЗагрузки`, `пр_ПрайсЗагрузка` | `пр_ЗагрузкаПрайсЛистов` |
| Подписка на событие | `пр_Подписка1` | `пр_ПроверитьЛимитЗаявкиПередЗаписью` |
| Общий модуль | `пр_РаботаСЗаявками` | `пр_Заявка`, `пр_ЗаявкаКлиент` |

Представление объекта (10.1.4):

| Свойство | Значение |
|---|---|
| Синоним | Заявка на закупку |
| Представление списка | Заявки на закупку |
| Расширенное представление объекта | Заявка на закупку товаров |

</details>

### 10.2 Состав и свойства

- **10.2.1** Новый объект сразу включается в подсистему, для него настраиваются права доступа и — если нужно — вывод в интерфейс.
- **10.2.2** Объекты верхнего уровня (справочники, константы и т. д.) отсортированы в дереве метаданных по имени. Подчинённые объекты (реквизиты, табличные части, формы) располагаются по логике проекта, а если её нет — тоже по имени.
- **10.2.3** Порядок значений перечислений и измерений регистров не сортируется и не меняется без анализа последствий: от порядка значений может зависеть логика (сравнения, `Индекс()`), от порядка измерений — индексы регистра (см. [«Не уверен — не трогай»](./04_methods.md#не-уверен--не-трогай)).
- **10.2.4** Если максимальная длина строки известна, реквизит получает именно эту длину. Если неизвестна — неограниченную. В запросах строку неограниченной длины, участвующую в выражении, приводят к строке фиксированной длины, достаточной для верного результата.
- **10.2.5** Строковые реквизиты — переменной длины. «Фиксированная длина» — только когда действительно нужна гарантия длины с концевыми пробелами.
- **10.2.6** Если элемент должен быть заполнен хотя бы в одном варианте работы, его свойство «Проверка заполнения» = «Выдавать ошибку», а у элемента формы `АвтоОтметкаНезаполненного` = «Авто». Где проверка не нужна, элемент убирается из проверяемых реквизитов в `ОбработкаПроверкиЗаполнения`.
- **10.2.7** Чтобы удалить объект, реквизит или табличную часть, захватываются все роли — иначе ссылки на удаляемый объект не удалятся корректно.

<details><summary>Примеры к 10.2</summary>

Строка неограниченной длины в запросе (10.2.4):

```bsl
// ❌ Плохо: сравнение и группировка по строке неограниченной длины не работают
|ГДЕ
|	Заявки.Комментарий = &Комментарий

// ✅ Хорошо: строка приведена к фиксированной длине
|ГДЕ
|	ВЫРАЗИТЬ(Заявки.Комментарий КАК СТРОКА(200)) = &Комментарий
```

Проверка заполнения средствами платформы (10.2.6):

```bsl
// Модуль объекта документа пр_ЗаявкаНаЗакупку

Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)

	// Склад обязателен только при доставке на склад
	Если НЕ ДоставкаНаСклад Тогда
		ОбщегоНазначенияКлиентСервер.УдалитьЗначениеИзМассива(ПроверяемыеРеквизиты, "Склад");
	КонецЕсли;

КонецПроцедуры
```

</details>

## Пояснения

### Почему общие модули — в объектном стиле, а остальное — нет

Имена объектов метаданных видит не только разработчик: они попадают в интерфейс, права, обмены, внешние отчёты и обработки, их знают пользователи, аналитики и внедренцы. Для них важнее всего привычность — совпадение с практикой 1С и типовых конфигураций. Поэтому такие объекты называются по стандарту 1С.

Общий модуль — контейнер кода, его видят только разработчики. Именно здесь объектный стиль решает свою задачу: по имени понятно, где лежит метод и каким объектом он управляет. Стандарт 1С регулирует в имени общего модуля только суффиксы контекста, а не порядок слов, — поэтому объектный стиль с ним не конфликтует.

> Правила о поддержке обычного приложения и толстого клиента перенесены в [Устаревшие правила](./99_deprecated.md).
