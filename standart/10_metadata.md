# 10. Объекты метаданных

[Оглавление](./README.md) | Назад: [9. Формы](./09_forms.md) | Далее: [11. Комментарии и описания](./11_comments.md)

## Правила

### 10.1 Имена и представления

- **10.1.1** Все объекты метаданных, кроме общих модулей, называются по [правилам 1С](https://its.1c.ru/db/v8std/content/550/hdoc) — естественным русским языком — с префиксом подсистемы (правило [2.1.8](./02_names.md#21-общие-правила)). Это относится и к хранимым объектам (справочники, документы, регистры, константы, перечисления), и к нехранимым (отчёты, обработки, подписки на события, регламентные задания, роли, функциональные опции и т. д.).
- **10.1.2** Общие модули называются в объектном стиле (правила [2.2.2–2.2.5](./02_names.md#22-объектный-стиль-имён)) с суффиксами по стандарту 1С.
- **10.1.3** Синоним осмысленно и кратко описывает объект. В мультиязычных конфигурациях синоним заполняется на всех языках конфигурации.
- **10.1.4** Представление объекта и списка (обычное и расширенное) заполняется, если представление, построенное по синониму, не подходит: например, неверно согласуются число или падеж.

<details><summary>Примеры к 10.1</summary>

| Вид объекта | ❌ Плохо | ✅ Хорошо |
|---|---|---|
| Справочник | `Склад`, `пр_СправочникСкладов` | `пр_Склады` |
| Документ | `пр_ДокументЗаявки` | `пр_ЗаявкаНаЗакупку` |
| Регистр сведений | `пр_Цены` (непонятно чего) | `пр_ЦеныПоставщиков` |
| Обработка | `пр_ОбработкаЗагрузки`, `пр_ПрайсЗагрузка` | `пр_ЗагрузкаПрайсЛистов` |
| Подписка на событие | `пр_Подписка1` | `пр_ПроверитьЛимитЗаявкиПередЗаписью` |
| Общий модуль | `пр_РаботаСЗаявками` | `пр_Заявка`, `пр_ЗаявкаКлиент` |

</details>

### 10.2 Состав и свойства

- **10.2.1** Новый объект обязательно включается в подсистему, для него настраиваются права доступа и, при необходимости, вывод в интерфейсе.
- **10.2.2** Объекты верхнего уровня (справочники, константы и т. д.) сортируются в дереве метаданных по имени. Подчинённые объекты (реквизиты, табличные части, формы) располагаются по логике проекта, а если её нет — тоже по имени.
- **10.2.3** Порядок значений перечислений и измерений регистров не сортируется и не меняется без анализа последствий: от порядка значений может зависеть логика (сравнения, `Индекс()`), от порядка измерений — индексы регистра (см. [«Не уверен — не трогай»](./04_methods.md#не-уверен--не-трогай)).
- **10.2.4** Если максимальная длина строки известна, реквизит имеет эту длину. Если неизвестна — неограниченную длину. Помните об ограничениях строк неограниченной длины в запросах: в выражениях их нужно приводить к строке фиксированной длины, достаточной для верного результата.
- **10.2.5** Строковые реквизиты имеют переменную длину. «Фиксированная длина» устанавливается, только если действительно нужна гарантия длины с учётом концевых пробелов.
- **10.2.6** У элементов, которые должны быть заполнены хотя бы в одном варианте работы, свойство «Проверка заполнения» устанавливается в «Выдавать ошибку», а у элемента формы `АвтоОтметкаНезаполненного` — в «Авто». Там, где проверка не нужна, элемент удаляется из проверяемых реквизитов в `ОбработкаПроверкиЗаполнения`.
- **10.2.7** Для удаления объектов, реквизитов и табличных частей захватываются все роли: это нужно для корректного удаления ссылок на удаляемый объект.

<details><summary>Пример к 10.2.6</summary>

```bsl
// Модуль объекта документа пр_ЗаявкаНаЗакупку

// BSLLS:MissingParameterDescription-off - см. синтакс-помощник
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)

	// Склад обязателен только при доставке на склад
	Если НЕ ДоставкаНаСклад Тогда
		ОбщегоНазначенияКлиентСервер.УдалитьЗначениеИзМассива(ПроверяемыеРеквизиты, "Склад");
	КонецЕсли;

КонецПроцедуры
// BSLLS:MissingParameterDescription-on
```

</details>

## Пояснения и рекомендации

### Почему общие модули — в объектном стиле, а остальные объекты — нет

Объекты метаданных видит не только разработчик: их имена и синонимы попадают в интерфейс, права, обмены, внешние отчёты и обработки, их знают пользователи, аналитики и внедренцы. Для них главное — совпадать с привычной практикой 1С и типовых конфигураций, поэтому они называются по стандарту 1С.

Общий модуль — это контейнер кода, его видят только разработчики. Именно там решается задача, ради которой введён объектный стиль: чтобы по имени было понятно, где лежит метод и каким объектом он управляет. Стандарт 1С не задаёт порядок слов в имени общего модуля, а только суффиксы контекста, — поэтому объектный стиль с ним не конфликтует.

> Правила про поддержку обычного приложения и толстого клиента перенесены в [Устаревшие правила](./99_deprecated.md).
