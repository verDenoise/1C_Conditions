# 6. Условия и циклы

[Оглавление](./README.md) | Назад: [5. Переменные](./05_variables.md) | Далее: [7. Исключения и транзакции](./07_exceptions.md)

## Правила

### 6.1 Условия

- **6.1.1** Каждое ветвление удваивает число путей выполнения, поэтому ветвлений должно быть как можно меньше. Пороги сложности метода совпадают с порогами [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) по умолчанию: когнитивная сложность — не больше 15, цикломатическая — не больше 20. Превышение обязательно обосновывается комментарием. Если в проекте пороги в BSL LS изменены, действуют настройки проекта.
- **6.1.2** Основной (ожидаемый) вариант обрабатывается в ветке `Если`, а не в `Иначе`.
- **6.1.3** Ветки `ИначеЕсли` располагаются в порядке убывания вероятности. Исключение — перебор законченного набора значений (перечисления, предопределённые элементы): тогда порядок соответствует порядку значений.
- **6.1.4** Сложное условие заменяется вызовом функции или промежуточными булевыми переменными. Условие, которое используется больше одного раза, обязательно выносится в функцию.
- **6.1.5** Длинные цепочки условных операторов выносятся в отдельный метод.
- **6.1.6** Порядок вычисления сложных логических выражений задаётся скобками явно.
- **6.1.7** Пустая ветка `Если` запрещена: условие инвертируется, а код из `Иначе` переносится в `Если`.
- **6.1.8** Булевы значения не сравниваются с `Истина` и `Ложь` явно.
- **6.1.9** Двойное отрицание запрещено.
- **6.1.10** Простой выбор из двух значений записывается тернарным оператором `?()`. Вложенные тернарные операторы запрещены.

<details><summary>Примеры к 6.1</summary>

Основной вариант первым:

```bsl
// ❌ Плохо: читатель сначала продирается через исключительный случай
Если НЕ ЗначениеЗаполнено(Договор) Тогда
	ДоговорОшибкаСообщить(Отказ);
Иначе
	ДоговорУсловияПрименить(Договор);
	ДоговорСрокиРассчитать(Договор);
	ДоговорЛимитПроверить(Договор, Отказ);
КонецЕсли;

// ✅ Хорошо
Если ЗначениеЗаполнено(Договор) Тогда
	ДоговорУсловияПрименить(Договор);
	ДоговорСрокиРассчитать(Договор);
	ДоговорЛимитПроверить(Договор, Отказ);
Иначе
	ДоговорОшибкаСообщить(Отказ);
КонецЕсли;
```

Сложное условие:

```bsl
// ❌ Плохо: смысл условия надо восстанавливать; поменяй одно «И» на «ИЛИ» — и результат непредсказуем
Если (Договор.Вид = ВидАгентский И Договор.КомиссияУчитывается И Ставки.Получить(Договор.Ставка) <> Неопределено)
	ИЛИ (Договор.Вид = ВидПоставки И Договор.ДатаОкончания <= КонецМесяца(ДатаРасчета))
	И Договор.Статус = Перечисления.пр_СтатусыДоговоров.Действует Тогда

// ✅ Хорошо: условие разложено на понятные части
КомиссияНачисляется = пр_ДоговорКомиссия.Начисляется(Договор, Ставки);
ПоставкаЗавершается = пр_ДоговорПоставка.ЗавершаетсяВМесяце(Договор, ДатаРасчета);
ДоговорДействует = (Договор.Статус = Перечисления.пр_СтатусыДоговоров.Действует);

Если (КомиссияНачисляется ИЛИ ПоставкаЗавершается) И ДоговорДействует Тогда
```

Пустая ветка:

```bsl
// ❌ Плохо
Если Документ.Проведен Тогда
	// ничего не делаем
Иначе
	ДокументПровести(Документ);
КонецЕсли;

// ✅ Хорошо
Если НЕ Документ.Проведен Тогда
	ДокументПровести(Документ);
КонецЕсли;
```

Явное сравнение с `Истина` и лишнее ветвление:

```bsl
// ❌ Плохо
Если ПроверкаПройдена = Истина ИЛИ ПроверкиОтключены = Истина Тогда
	ПроведениеРазрешено = Истина;
Иначе
	ПроведениеРазрешено = Ложь;
КонецЕсли;

// ✅ Хорошо
ПроведениеРазрешено = ПроверкаПройдена ИЛИ ПроверкиОтключены;
```

Тернарный оператор:

```bsl
// ❌ Плохо: пять строк ради выбора из двух значений
Если ДоставкаСрочная Тогда
	Срок = СрокСрочный;
Иначе
	Срок = СрокОбычный;
КонецЕсли;

// ✅ Хорошо
Срок = ?(ДоставкаСрочная, СрокСрочный, СрокОбычный);

// ❌ Плохо: вложенный тернарный оператор
Срок = ?(ДоставкаСрочная, СрокСрочный, ?(КлиентПостоянный, СрокЛьготный, СрокОбычный));
```

Двойное отрицание:

```bsl
// ❌ Плохо: какое условие здесь описано, читателю предлагается разобрать самостоятельно
Если НЕ (НЕ ОстаткиКонтролируются ИЛИ НЕ ТоварНедостаточно) Тогда

// ✅ Хорошо
Если ОстаткиКонтролируются И ТоварНедостаточно Тогда
```

### 6.2 Циклы

- **6.2.1** Тело цикла — не длиннее 15–20 строк. Длинное тело выносится в отдельные методы.
- **6.2.2** Вложенность циклов — не больше трёх уровней.
- **6.2.3** Служебные операции цикла (изменение счётчика, `Продолжить`, `Прервать`) располагаются в начале или в конце тела цикла, а не в середине.
- **6.2.4** В длинном цикле — один выход, и его условие очевидно. Много операторов `Прервать`, разбросанных по телу, — признак того, что цикл нужно переписать.

<details><summary>Примеры к 6.2</summary>

```bsl
// ❌ Плохо: тело цикла смешивает фильтрацию, поиск и заполнение, выходы разбросаны
Для Каждого ЦеныСтрока Из ЦеныТаблица Цикл
	Номенклатура = Справочники.Номенклатура.НайтиПоКоду(ЦеныСтрока.Код);
	Если Номенклатура.Пустая() Тогда
		Продолжить;
	КонецЕсли;
	НоваяСтрока = Документ.Товары.Добавить();
	НоваяСтрока.Номенклатура = Номенклатура;
	Если ЦеныСтрока.Цена = 0 Тогда
		Документ.Товары.Удалить(НоваяСтрока);
		Продолжить;
	КонецЕсли;
	НоваяСтрока.Цена = ЦеныСтрока.Цена;
	// ... ещё 30 строк
КонецЦикла;

// ✅ Хорошо: служебные операции в начале, работа — в отдельном методе
Для Каждого ЦеныСтрока Из ЦеныТаблица Цикл

	Если НЕ ЦенаЗагружаемая(ЦеныСтрока) Тогда
		Продолжить;
	КонецЕсли;

	ТоварыСтрокаДобавить(Документ, ЦеныСтрока);

КонецЦикла;
```

</details>

## Пояснения и рекомендации

### Нормальный вариант первым

Код, в котором основной сценарий идёт первым, читается по главной линии, а не через череду исключительных ситуаций. Это соответствует принципу «действие — как можно ближе к точке выбора».

### Логические функции вместо сложных условий

Выносить условие в функцию стоит, даже если оно используется один раз. Имя функции документирует смысл проверки прямо в коде — это лучше комментария, потому что код меняют, а комментарии часто забывают. Если условие используется несколько раз, функция ещё и избавляет от параллельных правок.

### Скобки

Не полагайтесь на то, что вы (или читатель) помните приоритет операций `И`, `ИЛИ`, `НЕ`. Скобки делают намерение явным. Но если без скобок условие непонятно, возможно, его лучше разложить на части.

### Утвердительные условия

Во всём коде используется единый стиль флагов: утвердительный. `Если ПроведениеРазрешено Тогда` читается легче, чем `Если НЕ ПроведениеЗапрещено Тогда`.

### Порядок вычислений

Платформа вычисляет логические выражения по сокращённой схеме: если результат уже известен по первой части, вторая не вычисляется. Поэтому, когда порядок не важен для смысла, ставьте первыми простые и дешёвые проверки, а тяжёлые (запросы, обращения к базе) — последними.

```bsl
// ✅ Запрос выполнится, только если флаг установлен
Если ОстаткиКонтролируются И пр_Остатки.Недостаточно(Товары) Тогда
```

### Циклы

Короткий цикл можно увидеть целиком. Если цикл хорошо спроектирован, его тело почти всегда можно вынести в один-два метода. Когда вы оцените преимущества простого кода, вы редко будете писать циклы длиннее 15–20 строк.

Способность разобраться в цикле заметно падает при вложенности больше трёх уровней. Если нужно больше, выделите внутренний цикл в метод. Смысловые имена счётчиков и элементов (правило [5.6](./05_variables.md)) уточняют и назначение цикла, и элемент, к которому идёт обращение.
