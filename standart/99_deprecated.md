# Устаревшие правила

[Оглавление](./README.md) | Назад: [18. Стиль работы](./18_work_style.md)

Правила из прежних редакций стандарта, которые потеряли актуальность для новых разработок, но могут быть нужны при сопровождении старых конфигураций или при работе на старых версиях платформы.

## Обработчики оповещений оформляются функциями

> **Устарело с платформы 8.3.18 (2020 год)**, в которой появились асинхронные функции `Асинх` / `Ждать`.

**Прежнее правило:** методы завершения асинхронных вызовов (обработчики `ОписаниеОповещения`) оформляются функциями, возвращающими `Неопределено`. Это позволяло при недоступности оповещений вызывать обработчик через `Вычислить`, так как `Выполнить` недоступен в мобильной платформе.

**Сейчас:** для новых разработок используются `Асинх` / `Ждать`. Обработчики `ОписаниеОповещения`, где они всё же нужны, оформляются обычными процедурами.

```bsl
// Сейчас
&НаКлиенте
Асинх Процедура ЗаказУдалить(Команда)

	Ответ = Ждать ВопросАсинх(пр_ЗаказТексты.УдалениеВопрос(), РежимДиалогаВопрос.ДаНет);

	Если Ответ = КодВозвратаДиалога.Да Тогда
		ЗаказУдалитьНаСервере();
	КонецЕсли;

КонецПроцедуры
```

## Представление ошибок функциями глобального контекста

> **Устарело с платформы 8.3.17**, в которой появился объект `ОбработкаОшибок`.

**Прежнее правило:** для журнала регистрации использовать `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, для пользователя — `КраткоеПредставлениеОшибки(ИнформацияОбОшибке())`.

**Сейчас:** одноимённые методы глобального контекста считаются устаревшими. Используются методы объекта `ОбработкаОшибок` (см. [7.1.7](./07_exceptions.md#71-попытка--исключение)). Для конфигураций на платформе ниже 8.3.17 прежнее правило действует.

## Поддержка обычного приложения

> **Актуально только для конфигураций, которые работают в режиме обычного приложения.** Современные типовые конфигурации (ERP 2, УТ 11, БП 3.0, ЗУП 3 и др.) работают только в управляемом приложении.

**Прежние правила:**

- Разработка ведётся в режиме «Управляемое приложение и обычное приложение». Всем клиентским модулям устанавливается флажок «Клиент (обычное приложение)». Код должен работать при любой настройке свойств конфигурации, которую 1С считает нормальной (см. требования «1С:Совместимо»). Аналогично используются инструкции препроцессора и заменяющие их функции.
- В чистой (не объединённой с типовой) конфигурации или расширении включается «Использовать управляемые формы в толстом клиенте в обычном режиме».
- Действия при старте системы отрабатывают в том числе в толстом клиенте обычного приложения.
