# 5. Переменные

[↑ Оглавление](./README.md)

> Как называть и использовать переменные. Общие правила имён — в главе [2. Имена](./02_names.md).

**Коротко**

- Одна переменная — одна цель и никаких скрытых смыслов в значениях.
- Для стандартных ролей — стандартные имена: `Результат`, `Отказ`, `Запрос`, `Выборка`.
- У «магических» чисел и строк есть имена.
- Переменная объявляется там, где впервые нужна.

## Правила

- **5.1** Каждая переменная служит одной цели. Переиспользовать её под другое значение запрещено.
- **5.2** У значений переменной нет скрытого смысла. Если `ФайловКоличество = -1` означает ошибку, это скрытый смысл: для ошибки нужна отдельная переменная или исключение.
- **5.3** Для стандартных ролей используются стандартные имена: `Результат`, `Отказ`, `СтандартнаяОбработка`, `Запрос`, `Выборка`.
- **5.4** Возвращаемое значение функции хранится в переменной `Результат`, которая инициализируется в начале функции (см. [4.3](./04_methods.md#43-функции)).
- **5.5** Счётчики и элементы циклов:
  - счётчик цикла `Для` заканчивается на `Индекс`, `Позиция` или `Номер`;
  - элемент цикла `Для Каждого` заканчивается на `Элемент`, а строка таблицы — на `Строка`;
  - во вложенных циклах имена отражают содержимое: `ТоварыИндекс`, `РеквизитыЭлемент`, `ДоговорыСтрока`. Без вложенности допустимы короткие `Индекс`, `Элемент`, `Строка`.
- **5.6** Булевы переменные называются утвердительно.
- **5.7** У «магических» чисел и строк есть имена. Без имени допускаются только `0` и `1` в очевидном контексте: начало нумерации, приращение.
- **5.8** Переменная объявляется рядом с местом первого использования. Исключение — переменная результата функции.

Одна переменная — одна цель:

```bsl
// ❌ Плохо: «Текст» сначала хранит тему, потом — тело письма
Текст = ЗаказЗаголовок(Заказ);
Письмо.Тема = Текст;
Текст = ЗаказОписание(Заказ);
Письмо.Тексты.Добавить(Текст);

// ✅ Хорошо
ПисьмоТема = ЗаказЗаголовок(Заказ);
ПисьмоТекст = ЗаказОписание(Заказ);
Письмо.Тема = ПисьмоТема;
Письмо.Тексты.Добавить(ПисьмоТекст);
```

Скрытый смысл значения:

```bsl
// ❌ Плохо: -1 означает «каталог недоступен»
ФайловКоличество = КаталогФайлыКоличество(Каталог);
Если ФайловКоличество = -1 Тогда
	// ...
КонецЕсли;

// ✅ Хорошо: признак доступности отдельно от количества

	ФайловКоличество = пр_Каталог.ФайлыКоличество(Каталог);
Иначе
	// ...
КонецЕсли;
```

Стандартные имена:

```bsl
// ❌ Плохо: своё имя для стандартной роли
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
	ЕстьОшибка = Ложь;
	// ...
	Отказ = ЕстьОшибка;

// ✅ Хорошо: параметр Отказ и есть признак ошибки
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
	// ...
	Отказ = Истина;
КонецПроцедуры
```

Вложенные циклы:

```bsl
// ❌ Плохо: во вложенном цикле непонятно, что есть что

	Для Каждого Строка Из Элемент.Товары Цикл
		// ...
	КонецЦикла;
КонецЦикла;

		// ...

КонецЦикла;
```

Цикл по индексу:

```bsl
// ❌ Плохо: выход за границу — индексы коллекций начинаются с 0
Для Индекс = 0 По Товары.Количество() Цикл

// ✅ Хорошо
ТоварыГраница = Товары.Количество() - 1;
Для ТоварыИндекс = 0 По ТоварыГраница Цикл
```

Магические числа:

```bsl
// ❌ Плохо: что такое 86400 и 30?

```

```bsl

```

## Пояснения

### Одна цель

Соблазн переиспользовать переменную, которая «уже отработала», появляется часто. Но тогда её имя подходит только к одной из ролей, а читатель вынужден следить, что в ней лежит сейчас. Две переменные с точными именами понятнее одной с размытым.

### Скрытый смысл

Когда разные значения переменной означают разные вещи — количество, если больше нуля, и ошибку, если `-1`, — это называют гибридным сопряжением. Такое поведение приходится описывать комментариями, и о нём легко забыть. Лучше, когда скрытых смыслов нет вовсе.

### Магические числа

`86400` понятно не каждому, `СекундВСутках` — каждому. К тому же именованное значение меняется в одном месте. Но не превращайте правило в догму: в формулах некоторые константы понятнее числом (`Радиус * 2`). Значения, которые повторяются по проекту, выносятся в функции модуля с повторным использованием или в константы.

### Короткие имена

Привычка сокращать имена переменных — пережиток. Короткое удачное имя получается, если убрать лишние слова или подобрать точный синоним, а не урезать слова. Перечитайте код, который не видели полгода: имена, непонятные с первого взгляда, — сигнал изменить подход к их выбору.
